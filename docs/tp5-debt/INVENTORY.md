# TP5→TP8 静默配置漂移 · 已验证清单

来源：43 个 agent 的并行审计 + 逐条对抗式证伪。候选 37，确认 23，驳回 14。

## [HIGH] view.view_path (admin/静态生成 入口)

- **TP5 生效值**：'template/<template_dir>/<html_dir>/' —— 前台主题目录，对 **所有** 入口（含 admin）都生效；只有当该主题目录不存在时才回退为 ''
- **TP5 证据**：application/common/behavior/Init.php:87-93 —— `Config::set(['view_path' => 'template/' . $TMP_TEMPLATEDIR .'/' . $TMP_HTMLDIR .'/'], 'template');` 紧接着 `if(ENTRANCE=='admin'){ if(!file_exists('./template/'.$TMP_TEMPLATEDIR.'/'.$TMP_HTMLDIR.'/')){ Config::set(['view_path' => ''], 'template'); } }`（注意回退是**有条件**的）。消费点：thinkphp_legacy_20260618/library/think/view/driver/Think.php:132 `$path = isset($module) ? APP_PATH . $module . DS . 'view' . DS : $this->config['view_path'];` —— 即不带 `@` 的模板名一律落到前台主题目录，带 `admin@` 的才落到 application/admin/view/。application/config.php:128 `'view_path'    => './template/',` 是同一语义的静态默认值。
- **TP8 生效值**：'' —— 对 ENTRANCE==='admin' **无条件**置空，被 think-view 解析为 application/admin/view/
- **TP8 证据**：application/middleware/AppInit.php:128-132 —— `if (ENTRANCE === 'admin') { \think\facade\Config::set(['view_path' => ''], 'view'); } else { \think\facade\Config::set(['view_path' => $viewPath], 'view'); }`。消费点：vendor/topthink/think-view/src/Think.php:184-188 `if ($this->config['view_path']) { $path = $this->config['view_path']; } else { $path = $this->getViewPath($app ?? $this->app->http->getName()); ... }`，getViewPath('admin')（同文件:143-160）返回 `$this->app->getBasePath() . 'admin/' . 'view/'` = application/admin/view/。
- **症状**：后台「静态生成」在 admin 入口下整体错乱，但两类后果要分清（原报告把碰撞面说大了一点）：

(1) 真实的模板碰撞 —— 只有 'index/index' 和 'topic/index' 两个裸名在 application/admin/view/ 下确实存在同名文件：
· ac=index → 把 application/admin/view/index/index.html（后台 layui 控制台外壳）渲染后写进站点根目录 ./index.html。webroot 的 index.html 通常优先于 index.php，公网首页因此变成后台面板外壳。
· ac=topic_index → 把 application/admin/view/topic/index.html（后台专题列表页）写进专题首页静态文件。
原报告顺带提到的 vod/index.html、art/index.html 并不会被命中：Make 走的是 mac_tpl_fetch('vod',$tpl,'type'|'detail') → 'vod/type'、'vod/detail'，只有当某分类的 type_tpl 恰好被填成 'index' 时才会撞上。

(2) 其余全部是 TemplateNotFoundException（500，生成中断）：map/index、rss/{index,baidu,google,so,sogou,bing,sm}、vod/type、vod/detail、art/type、art/detail、topic/detail、label/*。

另外两点值得记录：
· 该漂移不依赖中间件 —— config/view.php:4 本身就把 view_path 声明为 ''，即使删掉 AppInit.php:128-132 的 admin 分支，后台仍然是 ''。
· 同一份 Make 代码经 api.php 调用时 ENTRANCE='api'，走 AppInit 的 else 分支拿到主题路径，解析正常。所以「定时/API 触发的生成没问题，后台点按钮的生成坏掉」，这种入口相关的不一致会让排查更难。
- **该 agent 建议的补丁**：恢复 TP5 语义：AppInit 里对 admin 也先设成主题路径，仅当 `template/<t>/<h>/` 不存在时才置 ''；或最小改动——在 Make::__construct 里用 TP8 的正确命名空间显式切回主题目录 `Config::set(['view_path' => 'template/'.$TMP_TEMPLATEDIR.'/'.$TMP_HTMLDIR.'/'], 'view')`（注意必须是 'view' 而非 'template'，见另一条 finding）。若选前者，必须同时修掉 Batchplayer/Help/Datareplace/Rep/Resourcehub 这 5 个用裸模板名的控制器（它们的 Config::set(...,'template') 在 TP8 是空操作，目前只是被 view_path='' 恰好兜住）。

## [HIGH] database.database

- **TP5 生效值**：'maccms10' (the configured schema name)
- **TP5 证据**：application/database.php:5 — `'database'        => 'maccms10',`, loaded flat into the `database` config group by thinkphp_legacy_20260618/library/think/App.php:252-253 — `$filename = CONF_PATH . $module . 'database' . CONF_EXT;` / `Config::load($filename, 'database');`. So `config('database.database')` resolved to the schema name.
- **TP8 生效值**：null (key lives one level deeper and the flat path resolves to nothing)
- **TP8 证据**：config/database.php has only two top-level keys — line 3 `'default'     => 'mysql',` and line 4 `'connections' => [` — the database name is at `connections.mysql.database` (config/database.php:8 — `'database'        => env('DB_NAME', ''),`). `Config::get('database.database')` therefore returns the default `null`; TP8 loads config/*.php and never loads application/database.php.
- **症状**：Under TP8 `config('database.database')` (and `database.hostname` / `database.hostport`) resolve to NULL — verified by booting the app and dumping Config — so every `select * from information_schema.columns where table_schema = ?` bind is NULL and matches zero rows. Real consequences, in severity order:

1. Meilisearch multi-site index collision (worst, and not in the original claim). application/common/util/MeilisearchService.php:40-57 builds the default index UID from those three dead keys. TP5 produced `maccms_maccms10_405a83`; TP8 produces the constant `maccms_site_<hash>` for every install with prefix `mac_`. The function's stated contract (:36-38, "绝不串库") is broken: two maccms sites sharing one Meilisearch with no explicit `index_uid` now read and write the SAME index, so one site's titles surface in the other's search results. application/admin/controller/Meilisearch.php:30, :68 and :106 also auto-fill this colliding value into saved config.

2. The 安全 / 数据检测 XSS-and-{php} database scanner is a no-op that reports success. application/admin/controller/Safety.php:84 yields an empty `$col_list`, so the `foreach ($col_list as $k1 => $v1)` at :117 never executes; each table index just increments and the run ends at :93 printing `data_clear_ok`. An admin cleaning up after an injection is told the database is clean without a single row having been read. Same for the attachment consistency check: application/admin/controller/Annex.php:241 / :270 / :249.

3. `php think tune` always misreports MySQL. application/command/Tune.php:178 `if (Config::get('database.database'))` is permanently false, so the innodb_buffer_pool_size probe never runs and the report always says `mysql_connected => false, mysql_buffer_mb => 0`, suppressing the MySQL tuning advice.

4. Upgrader: all 60 `empty($col_list[...])` guards in application/data/update/database.php open, so the whole script is emitted on every run. The CREATE TABLEs and ALTERs fail and are swallowed by Update.php:154-158 (log full of ---fail). Exactly ONE table actually gains junk rows: mac_sign_milestone. The INSERT at database.php:485 is reached because the `empty($col_list[...])` branch at :474-476 sets `$milestoneNeedInsert = true` without ever consulting the row count, and on a site provisioned from application/install/sql/install.sql the table has only a non-unique `KEY milestone_days` (install.sql:1350) — so 6 duplicate milestone rows are appended per upgrade run, and users see each sign-in milestone repeated. Sites whose table came from the upgrade path are immune (that CREATE declares `UNIQUE KEY milestone_days`, database.php:452). mac_task, mac_live_category and mac_live are NOT affected.

5. Cosmetic: SQL backups written by application/common/util/Database.php:77-79 carry an empty `-- Host / -- Port / -- Database` header.
- **该 agent 建议的补丁**：Change these call sites to `config('database.connections.mysql.database')` (or better, `Db::connect()->getConfig('database')` / the SQL function `DATABASE()`), matching what application/common/model/Base.php:20-21 already does for the connection name and prefix.
