## 为什么不是逐条打补丁

那 23 条不是 23 个 bug，是同一件事的 23 个投影：应用跑在 TP8 上，形状还是 TP5 的。
逐条修完，产生它们的七个配置平面一个没少，下个月照样复发。

这一类缺陷的共同特征是**全程零报错**，只是安静地和老站不一致，
只能靠用户用出来才发现，潜伏期以周计。方案的第一优先级是让这一类变响
（`php think mac:selfcheck` 是起点，`mac:effective` 生效值基线是核心）。

## 已知会复发的坑

见 `PLAN.md` 第 1 节的 RC1–RC8。最容易重犯的三条：

1. **改了 `config/` 或 `application/` 下的 PHP，不 reload php-fpm 不生效**（OPcache）
2. **`application/config.php` 是死文件**，TP8 完全不加载，在里面改任何东西都不会生效
3. **控制器命名走 `Str::studly()`**：`vodplayer`→`Vodplayer`，`sign_milestone`→`SignMilestone`，
   两组规则不同，不能一刀切（曾因此造成 5 组后台 404）
