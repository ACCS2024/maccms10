# CSV 导入的解析预算

日期：2026-09-10。此批只覆盖 `BulkTableIo::parseCsv` 及 CSV/TXT 的 `parseFile` 分支。

旧实现先用 `fgetcsv` 构造整份文件的数组，后台控制器随后才截取前 2,000 行。大量分隔符会在原生解析器中分配单元格；很少的输入列也会按宽表头填充大量输出单元格。上传字节限制和解析后的行限制不能约束这些分配。

新的解析器只读取一次有上限的原始字节，在每个逻辑记录交给 `str_getcsv` 之前计数。引号内的换行不拆行，双引号转义和原有空 escape 合同保留；原生解析得到的列数还须与扫描结果一致。解析使用已检查的同一份字节，不重新打开可能改变的源文件。PHP 原生函数的空 escape 参数关闭其专有反斜杠转义，符合前一批导出/导入往返修复。[PHP str_getcsv 手册](https://www.php.net/manual/en/function.str-getcsv.php)

| 预算 | 上限 |
| --- | ---: |
| 原始 CSV 文件，包括 BOM、分隔符和换行 | 20 MiB |
| 单个逻辑记录，不含记录结束符 | 8 MiB |
| 列数 | 256 |
| 逻辑记录数，包括空记录 | 表头 1 条，加 2,000 条 |
| 原生输入单元格，包括表头 | 100,000 |
| 按表头宽度补齐的输出矩阵 | 100,000 个单元格 |

超过任意预算即拒绝整份文件，不返回前半部分以供写入。未闭合引号或闭合引号后出现非空白杂项也会拒绝。CSV/TXT 都执行同一规则；空文件、仅 BOM、普通空行、UTF-8、CR/LF/CRLF、双引号、字面反斜杠和多行单元格保持正常行为。预算控制的是导入文件，不改变导出上限；超过导入预算的导出文件需要分批导入。

`tests/framework_audit_csv_budget.php` 使用 19 个独立 `memory_limit=128M` 进程，每版 96 项，分别核对每项边界和拒绝结果。20 MiB 合法文件峰值 54.02 MiB；100,000 个输入单元格峰值 14 MiB；2 MiB 连续分隔符受控拒绝，峰值约 4.01 MiB。上述为独立解析进程的 PHP 8.3/8.4 观测值，不等于完整应用的总内存保证。原有 CSV 普通回归、40 项真实导出往返和后台实际 CSV/XLSX 导出回归一同运行。

XLSX 的压缩项、XML、共享字符串和坐标预算仍待独立修复；目前后台导入仍调用 TP5 上传对象方法，接收入口升级尚未完成。本批不宣称后台导入功能已可投产。表头重复、超出表头的数据列、CSV 公式策略和逐行保存的一致性也需单独明确合同。
