# 提现金额与实际落库核验

提现报价共用已有的精确十进制计算，不再先转浮点、四舍五入再截取积分。例如金额 `0.29`、比例 `100` 必须冻结 29 积分。输入金额只接受可精确表示的两位小数，比例保留已有的小数配置能力，最终积分受提现 SMALLINT 容量限制。错误的最低金额/比例配置受控拒绝。

收款字段保留请求已经解码后的文字，避免把 `+` 再次变成空格或把字面 `%20` 改写。检查 UTF-8、控制字符及最终 HTML 编码后的实际列容量；收款人、账户和银行名称不能依赖 MySQL 静默截断。申请时锁内核对当前用户启用状态、可用积分和冻结积分容量。

申请回读完整的服务端字段、金额和两种余额；退款核对两种余额、被退款的原记录和实际删除结果；审核核对提现状态/时间、原记录、余额及实际新增台账的用户、类型、积分、时间。触发器改变值或非严格数据库截断导致不一致时整笔回滚。通用 `fieldData` 不再允许绕过申请/退款/审核直接修改资金记录。

专项 `framework_audit_cash_storage.php` 使用真实 SQLite/MySQL，覆盖小数误差、输入/配置、收款容量、停用用户、原账户身份和数据库实际改变字段的情况；财务与模型套件同时覆盖既有场景。本批没有改变已支付提现的删除/展示合同。提现历史保留、跨请求幂等/核对与管理端参数入口仍是后续工作，不能将精确落库解释为整个提现生命周期已审计完毕。
