# 附件事务的异常收尾

日期：2026-09-10。适用于 `LocalAttachment` 管理的手工附件、头像和下载图片资产；图片准备、Annex 精确写入和远端凭据引用的既有规则不变。

## 已确认问题

在真实 PDO 上，BEGIN 实际成功但确认抛错时，旧代码尚未设置事务标记，因而没有回滚。发布第二张图片失败后，若回滚也失败，旧 finally 会删除已经发布的第一张图片和私有准备目录，而原 PDO 中仍有三条 Annex 记录和活动事务。PHP 8.3、8.4 均复现了这两种状态。

## 当前处理

保存本次 owner 的原连接、主库 PDO 和 BEGIN 尝试状态；开始前拒绝已有调用方事务及自动重连配置。远端传输之后、元数据写入前后和最终提交前后检查连接身份与事务状态。检测到替换后的连接时不会回滚替换的 PDO。

失败只调用一次 ORM 回滚；若仍未确认原事务结束，仅对本次拥有的原始 PDO 补救一次，并重置损坏连接的 ORM 深度。移除连接引用不是物理回滚的证据。BEGIN 返回之前抛错也进入该收尾路径，已经意外结束的 owner 事务不会被误认成已确认回滚。

COMMIT 曾尝试但未确认仍保留 `commit_outcome_unknown`。未确认回滚或事务身份改变时保留 `rollback_outcome_unknown`、BEGIN 尝试/确认标记以及已有文件清单。两者均保留已发布文件和私有准备文件，防止删除仍可能被数据库引用的资产；同一 Request 的后续附件事务会在创建新准备目录之前拒绝。可确认回滚时才清理本次文件，正常成功仍按原规则清理。

对外维持既有上传失败响应或下载 `#err` 合同。诊断日志给出本次私有清单路径，未加入原异常、账户凭据或文件内容。诊断清单与原始数据库状态需要人工核对；保留文件不等同于断言上传成功。

## 验证

`framework_audit_attachment_owner.php` 在 16 个独立 SQLite 文件数据库进程中注入真实 ORM/PDO 的 BEGIN、ROLLBACK、COMMIT 前后确认故障，覆盖普通成功、调用方原生/ORM 事务、无法恢复的回滚和同请求再次上传。每个 PHP 版本 163 项，直接检查保留的原始 PDO、实际元数据、发布文件和私有清单。

下载资产既有提交故障夹具改用文件数据库，避免连接被正确重置后，内存数据库消失导致无法观察实际提交结果。专项之外运行双版本 upload/remote_upload 默认回归及对应 MySQL 回归，再运行本地/远端普通上传的实际 PHP/Chromium 回归。新增故障矩阵使用 SQLite；MySQL 项属于既有业务回归，不把两者混称为 MySQL 故障注入。

## 后续边界

独立 `StorageIntent` 事务的确认故障、调用方随后更新 Collect/Images/AI 资源字段的原子性、主动删除附件、跨请求持久操作编号和核对恢复工具仍需分批处理。本批没有自动重试、恢复、删除远端对象或根据单条附件记录自动宣布成功。Request 范围的阻止也不代替整个应用的数据库连接隔离。
