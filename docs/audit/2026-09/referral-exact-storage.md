# 分销奖励的精确持久化

既有 `User::reward` 已将三个层级的积分和账本放在事务内，但成功条件仍只依赖 UPDATE affected rows 和账本模型返回码。旧安装的窄字段或触发器可能在 MySQL 非严格模式下改变实际保存值，使被截断的积分与完整账本、或完整积分与被截断的账本一起提交。

本组保留奖励比例、取整、来源账号、层级和账本类型。在每个受益账号行锁内读取原余额，加分后要求写库余额精确等于原余额加奖励；账本写入后逐项读回核对用户、类型、积分和备注。任何层级不一致都回滚此前层级。User/Plog 任一 MySQL 表不是 InnoDB 时，在奖励写入之前拒绝，SQLite 保留；关闭奖励或零消费不写奖励，沿用既有短路行为。外层购买/升级事务仍拥有最终提交权。

`tests/security_audit_referral_storage.php` 复用隔离财务测试环境，在三个层级逐一改变账本归属、类型、金额、备注及实际余额，并验证完整回滚；另验证外层扣费事务回滚。MySQL 直接修改测试表字段宽度，在非严格模式下复现余额、账本金额和备注静默截断，并验证两张表的非事务引擎拒绝。测试不改生产结构、历史账本或外部服务。

PHP 8.3/8.4 下专用测试各为 SQLite 29 项、MySQL 37 项，通过后并入 `financial` 全套回归。实际奖励大于当前账本字段容量时会明确失败并回滚；需要更大容量的部署应由独立数据库迁移扩容，不能静默减少已承诺奖励。

本组解决分销函数的存储一致性，不改变分销规则、统一所有积分写入路径或修复历史不一致数据。内容购买的幂等扣款、真实资源校验和请求 CSRF 仍在后续购买链批次继续。
