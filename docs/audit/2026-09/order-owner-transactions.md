# 支付回调原事务收尾（F2c）

日期：2026-09-11，基于 `251e851b` 的独立修复批次。数据快照与落库精确性另列 F2d。

## 已确认行为

固定源在 PHP 8.3.33 / 8.4.25 的 SQLite / 安装 MySQL 上共 20 条真实故障观察：BEGIN 已执行后抛错，回调异常逃逸且原 PDO 活动；COMMIT 已执行后抛错，独立连接确认订单已支付但响应仅为普通 2004；充值台账失败且 PDO rollback 持续拒绝，订单状态和充值积分留在原连接中；会员私有 rollback 在执行前失败，回调返回 2005 后原 PDO 仍活动、ORM 层级为 1，订单和充值部分变更仍待提交。执行后才丢失 rollback 确认的另一情形最终被原 catch 清理，未误报为遗留。

## 修复合同

OrderTransaction 使用共享原 PDO 机制；BEGIN、前置查询和收尾都处于受控范围。回调负责物理提交，因此拒绝借用已有 ORM 或原生 PDO 事务，也不能把调用方未提交的 paid 行当作幂等成功。当前六个随附支付适配器直接调用该接口，没有应用侧包裹外层事务的调用者。

写入前检查当前 Order/User/Plog 实际表均可事务回滚。内层会员或返利清理不明时，由订单拥有者执行一次 ORM rollback，并在原 PDO 仍活动时进行至多一次原生完整回滚；确认整笔恢复后返回普通业务失败。无法确认清理、连接身份丢失或 COMMIT 确认丢失，则返回带诊断编号的未知结果并阻止同一上下文继续资金操作。保留真实外部到账金额比较、已有幂等和业务失败代码；六个适配器仍只确认 code 1。
