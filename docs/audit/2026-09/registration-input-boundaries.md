# 注册输入与初始字段边界（R1）

## 本组修复

`User::register` 原先分别对两个密码执行 URL 解码和 HTML 编码后使用宽松比较，却把第一个原始密码用于哈希。这会把某些不同原始内容当成相同确认密码；形如 `0e...` 的不同数值字符串也可能通过宽松比较。本组让密码必填检查、长度验证、严格确认比较和哈希使用相同的原始 trim 字节：长度 6～72 字节，两个输入都不允许 NUL。密码允许普通标点、百分号、加号和 Unicode，不进行第二次 URL 解码或 HTML 编码；超过 bcrypt 字节容量直接拒绝。

用户名保留既有规范化及 ASCII 字母数字规则，最少 6 个字符，并增加安装 DDL 的 30 字节上限。模型实际读取的文本参数要求字符串；缺少的可选字段使用空字符串。非密码文本要求合法 UTF-8 且无 NUL；第三方标识还受 40 字节和安装表 UTF-8 字符集限制，防止非严格 MySQL 静默截断。普通请求里的 OpenID 仍被清空，只有已有的服务端可信回调参数才可保留身份并获得原有挑战豁免。

`uid`、邀请码、验证码渠道和文本长度在任何写入前检查。邀请码先 trim，再验证现有生成格式可用的字母数字及 20 字符上限，避免账号创建后才因数组邀请码 `trim()` 报错。推荐人编号、初始积分、注册 IP、时间和计数配置复用 `PointsBalance::amount(..., true)` 的 uint32 边界，不把数组、浮点、负数或科学计数法字符串直接转换为有效字段。

注册开关、验证开关和初始状态严格接受整数或字符串 0/1；默认组在安装组编号范围内。缺少可选旧邀请基础配置 `invite_reg_points` / `invite_reg_num` 时使用 0，已经提供但类型或范围错误的配置返回受控失败。注册积分及每日限制等必要配置缺失也返回受控错误。过滤词和每日限制统一读取当前配置对象，不混用全局副本。

新账号显式写入 `bin2hex(random_bytes(16))` 生成的 32 字符会话随机数，避免注册后保留空会话秘密。哈希或随机数生成失败在写入前返回错误。原有请求限频、每日成功注册次数限制、验证码匹配、普通手机号/邮箱注册与服务端可信 OAuth 注册路径保留。

## 后续边界

R1 只收紧注册模型的输入及初始写入字段，不代表注册全流程已经安全。账号插入、验证码消费、邀请码写入、推荐关系、直接邀请积分及阶梯奖励尚未构成一个原子事务；部分下游失败仍可能留下已创建账号或不完整奖励。注册用户名和联系方式的并发唯一性、发送验证码和注册身份来源、邀请阶梯坏配置与财务上限、入口级参数归属，以及独立 `loginOrRegister` 路径都由后续 R2 分组闭合。本组未修改这些方法，也不加入会固化当前非原子行为的测试断言。
