# 本地附件暂存、完整登记与失败清理（2026-09）

本组依赖上传身份、CSRF 及 TinyMCE 响应修复，只处理新的普通本地附件。用户头像、云存储 SDK 的上传/删除策略及已有附件维护保持独立。

## 已确认问题

原 `Upload::upload()` 在检查内容之前将文件移入公开 upload 目录；签名检查拒绝之后仍可能留下文件。附件元数据保存结果未检查，第二张及后续缩略图没有登记。附件表写失败可留下无记录文件；主图 size 写 KB 浮点、第一张缩略图写字节，和附件页面按字节 `/1024` 展示不一致。

编辑器 `back()` 会 echo + exit。PHP exit 不执行外层 finally，原上传在 try 内直接调用编辑器会绕过清理。仅增补 finally 无法修复该问题。

## 本组接口边界

- `flag != user` 且 mode 为 `local` 或字面 `remote` 时走 `LocalAttachment`。后者是原有“远程访问”选项，现有代码的手动上传仍保存本地，不调用上传 SDK。本组维持此行为。
- upyun/qiniu/ftp/s3 等供应商及数字旧别名、所有头像仍使用原处理分支。`Upload::api()`、`StorageResult` 和头像读取 helper 不变。
- 提取内部不输出/退出的 `processUpload()` 结果，由 `upload()` 在处理、清理与事务结束后调用统一编辑器响应。只读编辑器 config GET 仍在没有任何上传资源/事务时返回。
- `Image::prepareLocalUpload()` 为新本地流程严格准备图片。旧 watermark/makethumb 的其他调用者没有改换处理策略。

## 本地处理行为

1. 通过现有身份/权限/方法/CSRF 校验后，为本请求建立随机、权限 0700 的系统临时目录。接收 HTTP UploadedFile 或已支持的 base64 图片。
2. 在临时目录执行原有首尾签名检查；图片始终真正解码并检查格式与扩展名，即便未启用水印/缩略图。图片限额沿用 `ImageProcessor`。该签名启发式不等于完整病毒扫描，未扩大为文件内容安全的全面保证。
3. 启用的水印和要求的所有缩略图必须准备成功；每张缩略从同一原图派生、动画与水印语义沿用已有图片处理器。中途处理失败不会发布部分结果。
4. 为主文件和全部缩略图生成随机新路径；拒绝超出 Annex `INT UNSIGNED` 的实际字节数。用户响应 `size` 仍保留原 KB 表达，**新 Annex 一律存字节整数**。不重写历史单位混合记录。
5. 本次操作独占数据库事务，拒绝嵌套事务提前确认；MySQL 要求真实 Annex 表使用 InnoDB。在同一事务中逐条检查 `Annex::saveData()` 返回值，并从主连接读回唯一匹配记录，核对路径、类型、字节数、有效 ID 与服务器时间范围。非严格数据库截断、触发器改写、忽略写入均不能被当成成功。
6. 所有图片准备及元数据检查完成后发布文件。文件以排他新建方式打开，不覆盖已有名称；检查完整写入、flush/fsync、实际长度及 SHA-256 与暂存内容一致。拒绝符号链接目录，发生故障回滚元数据，并只删除本请求创建的文件和仍为空的本请求目录。
7. 正常提交后清除临时文件，再输出编辑器/普通 JSON。所有缩略图都登记，不仅第一张。

## COMMIT 不确定性与崩溃边界

数据库 COMMIT 报错可能发生在服务器已提交但确认包丢失之后，不能把它一律视为“没有提交”并删除可能被引用的文件。本组此时受控失败、保留完整新文件和私有 `manifest.json`，在日志记录核对位置。清单包含站点根目录、附件表名、创建时间和本次文件记录，不包含凭据。操作人员应按清单核对对应数据库与文件；没有确认引用状态前不自动删除。

明确的校验、处理、元数据写入或文件发布失败会回滚并清理本次文件。进程强杀/系统崩溃仍可能留下本次文件或临时目录，数据库事务不能提供跨文件系统的崩溃原子性；本组不自动清扫历史数据。后续独立维护工具才能按站点/操作清单、数据库引用与文件状态安全核对清理。

## 验证与复现

`php tests/security_audit_local_attachment.php`：PHP 8.3.33、8.4.25 × SQLite/MySQL 非严格模式，SQLite 每版 125 项、MySQL 每版 128 项通过。

使用真实 Request/UploadedFile、图片库和 ORM，覆盖：正常多缩略图全部登记且大小精确，正常 PDF/媒体/空文本，实际稀疏文件超过 UINT32 上界；坏图片/后缀不符/签名拒绝，第二个尺寸失败及必要水印失败；SQLite/MySQL 触发器拒绝/改写、非严格 MySQL 裁剪、非事务表；短写、第二文件发布失败、等长内容损坏、已有文件名碰撞、外部目录符号链接；权限/CSRF 拒绝、嵌套事务。

独立子进程还覆盖非异常 Annex 错误返回（含已经执行 INSERT 后返回失败）、真实非 root 文件权限失败、五种编辑器成功/失败 exit 后的清理与全部登记。COMMIT 的提交前/提交后异常使用真实 SQLite 驱动的窄故障覆写，分别证明无提交和已提交时都不会误删可能引用的文件；测试结束只移除自己记录的模拟核对目录。

既有回归：上传身份 203、CSRF 56 在两 PHP × 两数据库通过；图片上传 38、图片处理 111、TinyMCE 真实 HTTP 协议 104 在两 PHP 通过。原图片 fixture 的 Annex 假返回已换成真实隔离 SQLite，避免新流程的事务/读回被假数据绕开。

MySQL 仍用上传专用 `maccms_audit_upload` 与 `upload_audit_` 前缀，设 `UPLOAD_AUDIT_MYSQL=1`，可设 `UPLOAD_AUDIT_HOST/PASSWORD`。测试会重建该专用 fixture 的四张表，与其他上传数据库套件串行运行；不连接生产。SQLite worker 的自定义驱动常量仅存在于测试 fixture，默认行为不变。日志：`/tmp/maccms-audit-20260910/local-attachment/`。
