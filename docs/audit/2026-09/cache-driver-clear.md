# 缓存驱动清理边界

锁定依赖中的文件缓存驱动忽略子文件删除失败，Redis 驱动忽略 `flushDB()` 返回值，两者均可能错误报告成功。应用层现在通过文件驱动子类和 Redis 驱动覆盖修正这些返回契约，保留原文件存储格式、TTL 和 Redis 数据库选择。生产配置与后台连接探测使用同一文件驱动，无需修改 vendor。

文件缓存只清理配置的目录及命名空间：普通目录递归删除，已不存在的目录允许重复调用；根目录链接、断链、链接祖先、不可访问祖先和普通文件误配置均返回失败。子目录中的链接只删除链接条目。清理一个 prefix 不影响同级 prefix；保留框架将字符串 `0` 视为空 prefix 的存储语义。无效 prefix 不进入删除流程。该批只改变清理行为，不宣称文件驱动的并发读写、锁、序列化或所有配置输入已完成审计。

PHP 8.3.33、8.4.25 各执行文件驱动 32 项普通检查、UID/GID 65534 下 36 项检查，覆盖真实权限不足及恢复。Redis 故障客户端验证 false 和异常传播；隔离的真实 Redis 服务验证成功清理所选数据库、其他数据库数据保留、ACL 拒绝。现有目录清理、CLI 清理、缓存连接及完整默认审计同时回归。真实服务全部由测试创建，不连接站点缓存。

`Dir::clearDirectory()` 表示清理实际目录，拒绝根链接；`Dir::delDir()` 继续支持移除链接条目。二者共享路径边界。PHP 路径检查与删除之间仍存在系统调用竞态，不保证抵抗拥有目录写权限的恶意进程并发替换路径；Windows 原生行为尚未验证。
