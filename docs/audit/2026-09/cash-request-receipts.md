# 提现请求的持久化幂等

`user/cash` 的 POST 和 `cash/create` 现在必须提交 `request_id`：由调用方生成的 32 个随机字节，以 64 位小写十六进制表示。重试沿用该编号。账号来自重新验证的登录状态，不能由请求参数选择。

`cash_request` 保存账号、请求编号、规范化金额/收款字段的 SHA-256、原提现编号及创建时间。账号与请求编号组成主键。现金模型锁定账号后检查凭据，余额冻结、提现记录和凭据由同一原始 PDO 事务提交；凭据插入失败、字段被截断或触发器改变财务行都会回滚。已有凭据返回原申请的确认结果，即使当前兑换配置已经改变；同一编号携带不同内容则拒绝，并要求先核对原申请。

凭据不随普通提现记录删除而删除，因此撤销或已处理申请的重放不能再次冻结积分。它保存的是原申请已创建的事实，并不表示原申请当前仍在待审核状态。创建时不会通过请求路径执行 DDL；缺少凭据表或使用非事务引擎会拒绝写入。

默认和旧会员主题在发送前把随机编号保存到当前标签页的 `sessionStorage`，不在其中保存收款信息。断连、刷新及在凭据查询前发生的身份/限流拒绝都保留编号。只有返回的成功结果同时匹配请求编号和有效提现编号才清除它；同一页面的不确定结果仍锁定提交，用户核对后刷新重试会沿用原编号。客户端锁定不能代替服务器幂等：测试保留了响应头前断连、产生多次 POST 到达的情况。

## 数据库与调用方升级

新安装 SQL 包含 InnoDB 凭据表。已有站点先使用独立 CLI 脚本预检，确认后按站点发布流程应用新增表，再切换代码及两套模板。自定义客户端同时增加 `request_id`；Cookie 认证仍需上一批增加的会话令牌。

```sh
# 环境变量指定目标，脚本不读取站点配置或推断生产数据库。
# CASH_REQUEST_SCHEMA_DSN=mysql:host=...;dbname=...;charset=utf8mb4
# CASH_REQUEST_SCHEMA_USER / CASH_REQUEST_SCHEMA_PASSWORD
# CASH_REQUEST_SCHEMA_PREFIX=mac_
php migration/create-cash-requests.php
php migration/create-cash-requests.php --apply
```

默认只读。已存在但定义、主键或引擎不兼容的表需要处理预检阻断项；脚本不重写已有凭据，也不隐式提交调用方事务。普通取消、清理和回滚版本时都必须保留凭据；回滚到不支持凭据的旧写入口前，应关闭提现写入并按账务记录核对。

## 验证与边界

专项覆盖 SQLite 与 MySQL 的重复请求、规范化等价参数、内容冲突、跨账号隔离、配置变化、撤销/已付款后的重放、触发器失败/改变字段及余额、调用方事务和非事务表。MySQL 还运行两个独立 PHP 进程，同时争用同一账号；两者确认同一笔申请，只产生一次余额冻结。故障 PDO 分别在 COMMIT 前后抛出，独立连接核对实际数据，再以新请求重试原编号。
