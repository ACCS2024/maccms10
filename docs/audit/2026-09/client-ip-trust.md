# 客户端 IP 与可信代理

旧 `mac_get_client_ip()` 依次接受多个来源，又用最后一个合法值覆盖此前结果。`127.0.0.1` 等保留地址被排除后，请求头可能冒充连接来源；私网或公网代理又可能覆盖真实客户端地址。该函数还使用函数级静态缓存，不能随同一进程中的 Request 实例切换。框架 `Request::ip()` 和旧函数没有统一合同。

本批由 `ClientIp` 统一生产 Request 绑定和旧函数。默认只使用当前 Request 的 `REMOTE_ADDR`，允许合法 IPv4/IPv6、私网和回环地址，不凭地址类别推断代理身份。非法连接来源为 `0.0.0.0`，不会从请求头补出一个身份；地址按 `inet_pton` / `inet_ntop` 规范化。没有静态 IP 缓存，也不读取环境中的 HTTP 请求头或另一个请求的 `$_SERVER`。

`config/client_ip.php` 提供两个服务端配置项，可由环境配置注入：

| 变量 | 默认值 | 合同 |
| --- | --- | --- |
| `CLIENT_IP_TRUSTED_PROXIES` | 空 | 逗号分隔的代理 IP/CIDR；也可直接在配置文件使用字符串列表 |
| `CLIENT_IP_FORWARDED_HEADER` | `x-forwarded-for` | 只选一个：`x-forwarded-for`、`x-real-ip`、`cf-connecting-ip`、`ali-cdn-real-ip` |

部署时仅列实际受控代理的连接地址和网段。代理必须覆盖单地址头，或对 X-Forwarded-For 正确追加直接连接方的地址。若 Web 服务器已通过可信代理模块改写 REMOTE_ADDR，应用可以保持默认配置，不再解析一次代理头。应用不会自动信任私网、回环或某个云厂商，也不会根据收到的头自动下载/更新信任名单。这里仅处理客户端 IP，没有改变 Host、scheme、HTTPS 或 URL 生成的代理规则。

X-Forwarded-For 从连接来源向左解析：只越过已明确受信的代理，一旦遇到首个不受信来源就返回它，其左边的客户端输入不参与判断。单地址头拒绝逗号列表。所需节点非法、头类型错误、头超过 8192 字节或需要越过 32 个代理时，使用已知的连接来源。CIDR 使用地址字节与掩码比较，支持非整字节前缀；IPv4 和 IPv4-mapped IPv6 不自动互相匹配。配置最多 128 项，非法类型、地址或前缀明确报配置错误，经过已有异常处理器返回受控 500，不能悄悄扩大信任范围。

正常直连无需改配置。反向代理部署应先核对其连接地址和实际头协议；改变客户端 IP 计算结果后，原有绑定 IP 的后台会话可能需要重新登录。旧函数调用者的限流键、审计记录、后台登录校验及支付客户端 IP 将使用同一结果。

验证入口 `tests/framework_audit_client_ip.php` 使用真实 MacApp/provider、框架 Request 与异常处理器，并启动只监听 loopback 的 PHP HTTP fixture；覆盖头协议选择、默认不信任、多个代理、地址家族、CIDR 边界、非法 PHP 类型、请求切换、配置错误和真实 HTTP 初始化。没有连接真实代理或外部服务。另运行已有请求方法和默认回归，以及实际 HTTP 边界与后台会话相关回归。

本批不迁移数据库中的 UINT32 IP 字段；`mac_get_ip_long` 对 IPv6 的表达能力仍是独立迁移项。区域限制使用的内置省份库仅支持 IPv4，旧 GeoIp2 异常 catch 并不意味着缺包会直接致命；IPv6 地理归属、数据更新及未知归属策略仍需独立治理。
