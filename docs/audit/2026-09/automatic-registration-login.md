# 自动注册与登录契约（R3）

## 真实入口及修复

默认主题的完整登录页与 AJAX 登录弹层均调用 `api.php/user/login_or_register`。原路径重复实现账号创建，未遵循 `reg_open`、注册验证、注册事务及一致的会话规则。普通 `api.php/user/login` 还读取了模型未返回的 `info`，丢弃验证码，且两个接口都混读 URL 与正文凭据。安装 DDL 没有 `user_exp` 字段，直接读取也会触发 PHP 错误。

本组把 R2 注册实现下沉为私有 `createAccount`，由服务端选择普通注册或一步注册模式，外部请求不能选择可信 OAuth 身份或跳过挑战。普通注册仍要求至少 6 字符用户名；原一步注册的 3..30 字符规则保留，已有短用户名继续登录。一步注册在同一创建事务中完成初始积分、邀请码、推荐奖励和首次登录字段；会员组缓存读取也在提交前完成。提交成功后才设置浏览器 Cookie，任何数据库/密码计算/会员组读取失败均不会提前写 Cookie。

启用注册验证码、邮箱或短信验证时，新用户会得到 `registration_required=1`，实际前端导航到同站注册页面并保留已校验的邀请码。账号、密码不会放入跳转 URL。已存在账号只遵循登录验证码要求。默认完整页与弹层补充了实际登录验证码输入及图片，错误响应会清空并刷新验证码；需要审核的新账号返回 `pending_approval=1`，界面显示审核提示，不把未登录状态当作登录成功。

两个 API 登录方法和 index 登录改为只读 POST 正文。登录页 GET 仅依据 A2a 已验证的请求用户身份中的有效正整数 ID 决定跳转，展示 Cookie 本身不能让未认证用户陷入跳转或被当作已登录。普通 API 登录显式使用模型 `return_info` 契约，信息输出仍限制于当前账号所需字段；文档已有的 `type=name|email|phone` 通过服务端白名单映射，未指定时保留用户名/邮箱自动识别。缺失的可选扩展字段 `user_exp` 返回兼容默认值 0。原 `Auth::jwt` 的 `set_cookie=false/return_meta=true` 模型调用契约保留。

## 一致的密码与会话写入

普通登录和一步登录复用同一个模型登录方法。已有账号在事务中锁定并重新验证唯一身份，防止并发密码重置后继续使用旧快照建立会话。现代密码仅匹配原始 trim 字节，不接受 bcrypt 第 72 字节之后的别名。确为 32 位十六进制 MD5 的旧账号保留已有原始/历史编码验证兼容，成功后按原始口令升级。

密码升级、随机会话值、登录时间/IP、上次登录信息和计数写入同一条 UPDATE，并读回比对实际存储。旧 MD5 超过 72 字节的密码仍能精确登录，但保留旧哈希，等待显式改密，避免透明升级造成 bcrypt 截断。时间、IP、计数和会员组状态遵守实际字段边界；计数溢出、非事务 User 表及旧窄字段截断均受控拒绝并回滚。

重复或含糊的历史身份记录不会被随机挑选用于登录。一步登录已经按用户名确认的旧账号保持 `identity_field=user_name`，邮箱形式的历史用户名不会在下一步自动切换到其他账号的绑定邮箱；专门的对照账号测试验证两者凭据不能互换。模型的内部身份字段和返回选项仅由服务端调用参数决定，HTTP 表单不能选择任意列或取得会话元数据。OAuth 的无密码登录仍要求已有明确的服务端 `trusted_oauth` 选项及允许的身份列；普通请求传同名字段不生效。

## 验证与隔离

`framework_audit_auto_registration.php` 使用安装 DDL 的真实 User/Msg/Plog/Group ORM，验证正常及短用户名注册、Cookie 实际认证、原始密码/历史 MD5、验证码、审核状态、API 与 index 实际路由、配置边界、故障完整回滚、非严格旧窄字段及非事务引擎。

MySQL 独立 PHP 进程还同时提交普通注册与一步注册，检查姓名/IP 额度、初始账本和一次性推荐奖励；同时执行已有账号登录与密码重置，确认重置凭据和验证码消费最终保留。所有数据库连接使用专用注册审计库，不读取生产凭据，不调用真实短信、邮件或 OAuth 服务。

`framework_audit_auto_registration_views.php` 使用真实 ThinkTemplate 渲染默认完整页/弹层的实际表单片段，分别打开、关闭登录验证码。`framework_audit_auto_registration_frontend.js` 执行三处实际响应回调，验证站内注册导航、拒绝外站导航、审核提示、验证码清空刷新及正常登录行为。两份脚本引用版本同步更新，确保现有页面加载新行为。

当前新增检查数：SQLite 157、MySQL 非严格模式 177、模板渲染 14、前端行为 30；PHP 用例在 8.3/8.4 验证。R1/R2、改密、表单、消息、绑定和 OAuth 的既有回归同步运行。

## 明确的后续边界

本组已经消除旧 `loginOrRegister` 独立非原子创建流程，统一使用 R2 的同源锁和事务。R2 文档中的该项后续工作由本组完成。后台/OAuth 其他账号写入与全库唯一索引迁移仍未全部纳入应用锁覆盖，不能据此宣称全表身份唯一性。`Auth::jwt` 控制器当前仍混读 query/POST，普通 API 的 `find_password` 还调用错误用途的消息方法；这两处已上报主任务，需作为后续独立入口组处理。
