# 提现会员写入口与浏览器会话

会员 `user/cash` 写分支、`user/cash_del`，API `cash/create`、`cash/del` 同时要求原生及有效方法为 POST。参数只读正文；Cookie 身份必须验证当前会话令牌，启用且实际验证成功的 Bearer 身份按既有认证协议处理。构造链不在授权前持久化过期会员组。

创建通过 `saveForUser` 显式传入已验证的账号；请求中的账号、积分、状态和旧全局余额不作为创建凭据。取消申请采用严格的正整数 ID 集合，上限 1,000 项，`all=1` 仍受账号范围限制。金额、收款字段、余额和事务规则由既有现金模型执行，模型中的不确定结果及核对编号原样返回。

默认主题及旧会员主题接入同源令牌 GET、带令牌的 POST。页面只允许一笔在途写入；确认成功后阻止表单原地再次提交，响应损坏、中断或服务端声明 `retryable=false` 时保留提示并锁定后续写入。令牌获取失败和明确的业务拒绝允许用户再次操作。

暂存代码快照验证：PHP 8.3.33、8.4.25，真实路由/会话和安装表结构下各 326 项 SQLite、326 项 MySQL 检查通过。既有现金模型 31、精确存储 99、事务归属 306、购买 CSRF 492、会员列表 43、表单 288、构造响应 136、API 运行 23、API 验证 149 项分别在两个版本通过。Chromium 使用实际发布的 jQuery 和两套提现处理脚本，68 项协议检查通过；运行方式为 `node tests/browser/cash_write.cjs`，依赖使用 `tests/browser/package-lock.json`。

验证限制和立即后续：浏览器测试首次在响应头发送前断开连接，同一 fetch 在测试链路出现多次 POST 到达，因此不能用页面锁定声称请求恰好到达一次。当前中断回归覆盖已收到响应头、正文中途断开；下一批必须增加数据库持久化请求凭据及重放测试。此提交不解决跨刷新/进程的幂等、已付款记录保留、管理端写入口，也不把客户端锁定描述为账务一致性保证。
