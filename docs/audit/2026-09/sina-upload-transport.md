# 新浪图床旧客户端：传输与失败合同

当前代码的 `application/common/util/SinaUpload.php` 仍在登录请求中关闭证书链及主机名验证，上传接口使用 HTTP，并启用 cURL verbose。`Weibo` 适配器实际引用该类；先前适配器回归隔离了它，因此那些测试不能证明这个内部客户端安全。此次只处理该客户端及调用方的失败回退，不混入远端对象与数据库一致性改造。

已改为固定 HTTPS 登录、上传入口，验证证书链及主机名，禁止跟随重定向及降级到 HTTP，连接/总时限为 5/30 秒。关闭 verbose；错误不返回上游正文、凭据或 Cookie。响应正文最多 1 MiB，响应头最多 64 KiB，只有 HTTP 200 才处理结果。登录表单用标准百分号编码，密码中的 `&`、`+` 等不会变成额外参数。只接受实际响应头中的单一 SUB Cookie；上传拒绝含换行、额外 Cookie 或其他非法形态的输入。

PHP 8 异常路径包括缺失/畸形配置、cURL false、不可读文件、空响应、错误 JSON、非数组结果、缺图片字段、非法 PID/尺寸/图片规格。均受控失败，适配器保留本地文件路径。正常 base64 与 multipart 上传保留；返回图片地址改为 HTTPS。旧 `getSubstr` 在左标记位于位置 0 时失败的问题同时修复。

配置刷新沿用当前 `mac_arr2file` 格式，但该助手没有返回写入结果；原来的 `=== false` 判断无法识别磁盘失败。本组在更新内存 Cookie 前严格读回实际生成文件。测试调用真实助手，并用实际目录占据目标文件来验证失败不能误报成功。此读回并未把共享配置写入改成并发事务或原子替换；全局配置写入一致性仍需要独立组统一处理。

`tests/security_audit_sina.php` 在关闭外网的容器内启动本地 Python TLS 服务，生成临时 CA 和两套证书。只在测试命名空间调整 cURL 的地址解析、端口和 CA，生产 TLS、重定向、编码及响应回调通过真实 libcurl 执行。覆盖可信证书成功、不可信证书和主机名不符时 HTTP 处理器未收到凭据、连接拒绝、HTTP 错误/重定向、正文/头超限、实际两种上传格式、参数与配置错误，以及真实 `Weibo` 调用与本地回退。测试临时文件和服务均在退出时清理。

未使用真实账户或请求新浪服务，因此不宣称这个历史私有接口目前仍受服务方支持。若服务拒绝 HTTPS 或更改协议，客户端会受控回退本地，不关闭验证或重新使用 HTTP。上游会话配置的并发保存、远端成功后 `keep_local=0` 与业务数据库提交的先后顺序，分别留给配置写入组和远程存储一致性组。
