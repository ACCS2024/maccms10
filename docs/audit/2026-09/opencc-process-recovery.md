# OpenCC 转换与失败恢复

实际 Debian OpenCC 1.1.9 CLI 不接受旧探测参数 `-V`，导致已安装工具被误报不可用；改用真实验证通过的 `--version`。保留 `.json`/旧配置名两个候选，但通过 LocalProcess 的 argv 与 stdin/stdout 完成转换；不再创建临时输入输出文件、不使用 shell，也不退回无超时的 shell_exec。官方[命令行文档](https://github.com/BYVoid/OpenCC#command-line)说明了 stdin 转换；本批另以独立原生二进制执行核对。

每次配置尝试最多 3 秒，输入最多 8 MiB、stdout/stderr 合计最多 16 MiB。仅正常退出的完整输出可作为结果；部分输出、异常或超量保留原文且不缓存为成功。成功转换保留首尾空白、CRLF。转换缓存改用 v2 命名空间，避免读取旧裁剪/错误降级结果；单值 64 KiB、进程内转换文本总量 4 MiB，原生句柄候选最多 32 个。

原生扩展调用捕获 PHP 8 类型错误，并保留两个历史参数顺序的兼容尝试；可用性必须实际转换成功，不能把安装函数或版本号直接当作转换成功。扩展边界使用 PHP 普通替身验证，未安装真实 PHP OpenCC 扩展。

双 PHP 验证分三层：34 项实际故障子进程、10 项扩展形状/失败替身，以及 17 项独立原生 OpenCC 转换。故障覆盖退出失败、部分输出、超时、大量 stderr、旧配置候选、恢复后重试同一原文、版本存在但转换不可用、缓存字节上限和缺失工具。CI 增加独立原生 CLI 安装与验证步骤；本地二进制只安装在隔离目录，未改动站点运行环境。
