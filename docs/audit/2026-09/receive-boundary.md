# Receive 接收接口的请求边界

范围：`application/api/controller/Receive.php` 七个采集动作，以及 `application/common.php` 的 `mac_interface_type()`。PHP 8.3 / 8.4 下启用 `E_ALL`，将 warning/deprecation 转成异常后验证。

修复前可复现：

- 缺少 `pass` 读取未定义键；`pass[]` 在常量时间比较之前发生数组转字符串警告。
- 数组形式的必填名称能穿过 `empty()` 校验，数组分类名称触发非法数组下标；未知分类名称读取未定义键。嵌套可选字段会流入采集器的字符串函数和数据库构造器。
- 分类映射只正确拆分部分换行形式；Unix LF 会将两行拼接。空行、无等号的行、缺失配置、指向已删除分类的映射都可能触发诊断。
- 接收密码进入采集器的数据包；非视频动作还把仅用于映射的 `type_name` 当业务字段传递。

请求处理保留既有 `3001`（关闭）、`3002`（密码错误）、`3003`（密码长度）、各动作 `2001`–`2004` 的必填错误码。结构化必填字段使用对应原错误码；结构化可选字段返回 `1001` 参数错误。密码必须是字符串，仍使用 `hash_equals()`；不记录或回显密码。分类 ID 必须为范围内的正整数、存在于当前分类缓存且属于当前模块。显式 ID 不再依赖可选的名称映射；未知、删除或跨模块分类均受控拒绝。采集器仍收到单条 `data` 及原有 `show=0` 调用协议，正文保留原值供既有内容净化处理。

映射兼容 `local-name=source-name`、CRLF/LF/CR 和旧 `#` 分隔符；忽略空行、缺少任一名称、无等号的行。只按第一个等号分隔，名称两端空白去除。重复来源名称保持最后一条配置生效；本地分类同名时保持现有分类遍历的最后一条生效，Receive 额外校验模块，因此歧义不会写入错误模块。映射缓存继续保存本地名称，每次用当前分类缓存解析，删除/改名的目标不再返回 ID。不存在的目标和结构错误的缓存条目被跳过。

验证：`php -d error_reporting=-1 tests/framework_audit_receive.php`。测试使用真实 TP8 Request、真实 Receive 和真实映射函数；Base 初始化、缓存及分类目录使用隔离夹具，Collect 使用记录器，不连接业务数据库、不读取站点秘密、不发起外部请求。覆盖七种合法动作、必填/可选数组参数、认证失败、超大/不存在/跨模块分类、名称映射、可选零值/空值和映射缓存变化。此测试验证接收边界和采集调用协议，不替代 Collect 各模型的真实数据库入库回归。
