# 留言公开入口的静态收口与正常业务回归

此前留言子任务的动态复现被工具自动安全审查中止，返回原因“possible cybersecurity risk”。原未完成脚本已移至执行环境单独保存，没有执行或记作通过。本批采用源码调用核对、明确字段构造和正常业务回归，不声称补齐被中止的动态复现。

前台与API提交现在共用新增留言服务，仅从正文提取内容、显示名和视频关联编号，身份来自真实User认证结果，审核状态/时间/整数IP/空回复由服务端构造。公开入口不向后台模型的编辑分支传递现有留言编号。两入口统一按功能开关、POST、验证码、登录要求、间隔与255/60字符字段容量处理；成功持久化后再设置间隔。

`gbook_rid` 表示视频报错关联，不是回复父留言；后台仍通过原留言行写管理员回复。关联视频须存在且公开，旧库缺回收字段时不自动变更表。公开API列表固定为已发布状态，并明确返回公开字段，不输出IP。API旧“举报留言”写入不存在的 gbook_up 列，也没有实际报告存储，现受控返回暂不可用；前台视频报错表单仍保留。

`tests/framework_audit_gbook_normal.php` 仅验证正常游客留言、真实会员登录、启用验证码、待审核消息、视频关联、管理员回复、发布后公开列表与IP不进入公开响应。使用真实User/Gbook ORM和隔离安装表结构，服务层外的词汇过滤/验证码/URL环境为明确fixture，无真实外部发送。原API缺省测试同时补齐当前真实留言字段。该正常业务回归不能代替完整攻击面动态验证；后续如条件允许，仍需独立评估未覆盖的安全输入与并发边界。
