# 会员提现读取边界

会员提现页和 API 列表共享整数分页规则：每页 1–100 条，默认 20，偏移最多 1,000,000。非法类型、零/负数、指数形式、超范围值返回参数错误；分页模板使用实际查询的页码和条数。模型再次检查分页，并限制旧 JSON 查询条件的类型、深度及字节数。数据库查询失败返回错误，API 不再把模型失败包成顶层 `code:1`。

`cash/get_list`、`cash/get_detail`、`cash/get_config` 接受文档规定的原生且有效 GET，参数从查询字符串读取。旧客户端若使用 POST 查询，需要改为 GET。列表状态只接受 0/1，详情编号受真实 `INT UNSIGNED` 存储范围约束。个人记录由重新验证的 Cookie 或已启用的 Bearer 身份限定，忽略请求声明的账号；身份读取不持久化过期会员组，也不额外从副本查询账号。配置接口保持公开，不返回个人信息。

配置接口原先把 `cash_ratio=0.5` 通过 `intval` 返回为 0。现在保留原有数值字段，小数比例正确返回；新增 `cash_ratio_decimal` 和 `cash_min_decimal`，提供无浮点舍入的规范十进制字符串。新客户端应使用字符串字段处理精确规则，最终资金计算仍由服务端负责。无效比例、金额和配置形状返回错误。旧数值字段为兼容保留，不能承诺表示超出 IEEE-754 精度的全部十进制位。

验证使用真实路由、Cookie/Bearer、会话、ORM 和安装表结构，覆盖账号隔离、身份失效、过期组只读、原生/覆盖方法、参数形状、状态筛选、分页、缺表错误及极小/极大精确配置。另有模型边界、真实会员控制器分页、API 验证器和金额算法回归。双版本 SQLite、MySQL 及完整默认审计由本阶段冻结索引运行；未访问生产数据库。
