# 管理端提现写入口

`cash/del`、`cash/audit` 在控制器内强制原生/有效 POST、当前管理员会话、具体操作权限及当前会话 CSRF 令牌。即使关闭旧后台 CSRF 开关或配置 `cash/*` 豁免，这些操作也不能跳过校验。管理员权限从主库重新读取，撤权和停用不依赖旧会话或副本数据。

只从正文读取选择：兼容单条 ID、逗号列表和正常 `ids[]` 复选框，严格拒绝负数、数组嵌套、命名索引、重复编码、越界编号及超过 1,000 项的显式选择。审核必须明确选择记录；清空使用明确的 `all=1`，不再通过伪造 `ids=1` 扩展范围。账号、现金记录、退款及审核结果仍由原始 PDO 事务和实际存储校验负责。

提现页使用专用按钮脚本，将范围放入 POST 正文并携带 meta 中的会话令牌。响应原样保留财务核对编号和 `retryable=false`；仅确认成功后刷新，结果不明则锁定该页后续操作。通用列表按钮的错误码转换和自动刷新不再承担这些财务写入。

完整模板渲染另发现 `cash_remarks` 不属于当前安装表结构，原模板会因缺键中断页面；该可选历史字段现在以空白展示缺失值。回归覆盖真实后台构造链、当前权限/会话、路由、SQLite/MySQL 财务表，以及真实模板渲染。浏览器使用实际模板中的五类操作按钮与发布脚本，验证选择范围、重复点击、令牌、不确定结果保留和拒绝后的显式重试。旧后台请求时 DDL、提现记录完整保留和清空批次资源预算仍单独跟进。
