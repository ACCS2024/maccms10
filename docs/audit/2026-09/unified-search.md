# 统一搜索：真实结果、公开可见性与 PHP 8 请求边界

本批只修改 `application/api/controller/Search.php` 的 `index`、`suggest` 及私有查询、输入和缓存助手。未修改单模块搜索建议、共享 `PublicContentQuery`、Meilisearch bridge、存储或购买流程。

## 已确认的问题

在当前安装 SQL、真实 ThinkPHP Request/ORM 与 MeilisearchService 下，修复前 PHP 8.3.33、8.4.25 均复现五项问题：

1. SQL 搜索的 `select()` 返回 Collection，后续数组判断令非空结果静默变为空列表，`total` 仍非零。
2. Meili 命中后的数据库 Collection 同样被丢弃。这不是 `rowsToRichItems` 参数 TypeError；原方法的数组说明只是 PHPDoc。
3. 数组关键字进入字符串函数触发 TypeError。
4. 带回收条件的查询抛错后，宽泛 catch 再次查询时移除了回收限制。真实查询监听器注入异常可确认第二次 SQL 未带该限制。
5. 统一建议缓存命中直接复用，发布后又隐藏的内容仍在返回结果中。统一富搜索缓存有相同提前返回结构，本批对两个出口全部扩查和回归。

另外，实际读写分离连接表明：默认读连接上的字段发现和业务回表不能保证 writer 的当前公开状态；仅在最后过滤，也无法补回先被旧副本遗漏的合法命中。

## 实施行为

SQL 与 Meili 回表都在实际 Collection 上调用 `toArray()`，保持原富结果的 22 个公开字段、各模块独立分页、SQL 排序、LIKE 字段和 Meili 排名。统一建议保留原 7 个公开字段，并复用现有 `ApiMeilisearchSuggest::toSlimItem()` 映射器。

所有公开条件和行读取使用同一 writer。固定三模块表名由 ORM 得出，MySQL 使用参数化、只读 `information_schema.COLUMNS` 查询且显式 `master=true`；SQLite 使用参数化表信息查询。只有明确发现表和必需的 ID、发布字段后，才允许真正缺少回收列的旧表使用发布条件。字段发现或查询失败不移除条件重试，也不执行 DDL。字段确认仅在当前 Request 内，按实际连接对象和表缓存；不同请求、数据库和连接不能沿用旧证据。

两个结果缓存出口均检查公开 DTO 形状、模块、ID、数量与分页，再在 writer 确认全部源 ID 当前已发布、未回收且未删除。无效缓存重新查询；查询失败明确失败。新 `api_search_v2_` 前缀隔离旧格式，TTL 仍为 300 秒。有效缓存命中仍不消耗原有每 IP 30 次/60 秒的共享缺失配额；站点关闭搜索仍优先返回关闭状态。

Meili 命中仅接受当前模块的规范 UINT32 ID，限制数量并去重，再以实际数据库公开行恢复命中顺序。`index` 保留既有成功空命中，不额外 LIKE；`suggest` 对空命中、无可见命中或服务失败保留 LIKE 回退。服务返回失败仍允许有公开条件的 SQL 回退；未预期异常、DB 或缓存异常返回 `code=1002`，服务端记录异常类型和文件位置，响应不回显 SQL、凭据或内部异常文本。成功、参数错误、关闭、限流的既有响应结构与代码保留。

## 参数兼容策略

| 参数 | 保留的正常输入 | 明确拒绝的输入 |
| --- | --- | --- |
| `wd` | 字符串或整数，包括 `0`；trim 后非空；超过 50 个 Unicode 字符仍截断 | 数组、对象、布尔、浮点、缺失/空值、无效 UTF-8、非空白控制字符、超过 4096 原始字节 |
| `module` | 缺失/null/空值默认 all；忽略大小写和首尾空白；旧未知短字符串或整数仍回退 all | 容器、布尔、浮点或超过 32 原始字节 |
| `page`、`limit` | 缺失/null 使用旧默认；整数或完整十进制整数字符串，允许正负号和首尾空白；非正值仍归一为 1；limit 仍按端点限制 | 容器、布尔、浮点、空字符串、小数/科学计数法/尾随字符、超过 10 位数字/32 原始字节或超出 ±UINT32 |

分页在乘法前检查整数边界。SQL 按实际 `COUNT` 得到总数，偏移已超出总数时跳过深分页 SELECT。Meili 的 `estimatedTotalHits` 仍只是索引估计，合法深偏移继续传给服务；本批没有将索引估计当作精确数据库总数，也没有任意缩小合法页码范围。

## 边界与后续

- 其他公开列表和单模块建议使用的共享 `PublicContentQuery`、回表及 schema 缓存，仍需独立复核副本延迟和 writer 一致性；本控制器的修复不能证明那些路径已覆盖。
- 缓存校验保障源记录当前公开，不保证 300 秒内标题、排序、总数或新发布内容即时更新；不改变既有 TTL 语义。检查与网络返回之间仍存在一般的并发状态变化窗口。
- 通用非 Redis 限流仍保留原有非原子读写语义。本组没有声称提高其并发限流精度。
- MySQL 为本项目部署路径；SQLite 只提供只读 schema 分支。此次 392 项完整矩阵在 MySQL 上运行，不宣称完成 SQLite 搜索全矩阵或真实 Meili 服务性能压测。
