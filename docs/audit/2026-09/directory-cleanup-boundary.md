# 目录清理的尾斜杠与链接边界

在 PHP 8.4 的隔离目录复现：`Dir::delDir($linkedRoot . '/')` 返回 false，却已经删除链接指向目录中的哨兵文件。原实现先调用 `is_link`，而 POSIX 上带尾斜杠的路径会按目录目标解析；后台清理、采集后清理和 `cache:flush` 正好都传入 `runtime/cache/` 等带斜杠的目录。旧回归只覆盖无尾斜杠的根链接及子链接，漏掉了实际调用格式。

现在先验证路径并去掉末尾目录分隔符、`/.`，再检查链接条目；根链接和坏链接只删除链接本身。检查祖先路径，拒绝通过祖先符号链接进入另一棵目录树。拒绝空/非法类型、NUL、流包装器、文件系统根、当前目录以及 `..` 路径；普通目录仍支持尾斜杠并按原逻辑递归清理。符号链接形式的祖先部署路径需要改为明确的实际运行目录。

测试仅删除独立临时目录。覆盖普通元数据/迭代、外部目录链接、循环链接、根链接四种后缀、坏链接、祖先链接、非法路径及普通清理。文件系统根和当前目录的拒绝通过无副作用的路径验证器检查，测试不会把真实根目录交给删除函数。PHP 8.3/8.4 Linux 专项验证；Windows 路径规则有防御处理，但未执行原生 Windows 文件系统测试。

本批修复已观察到的确定性链接边界问题，不宣称能防御有权限并发替换任意目录的进程；PHP 路径操作没有提供完整的目录描述符相对删除合同。缓存清理调用方忽略 false 并报告成功的问题会单独处理，避免把目录算法与后台/CLI 结果合同混成一个提交。
