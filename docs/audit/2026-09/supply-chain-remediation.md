# MacCMS fork 供应链修复记录（2026-09-10）

依据[奇安信 XLab 对 FUNNULL / RingH23 / MacCMS 的分析](https://blog.xlab.qianxin.com/exposing-funnull-how-ringh23-maccms-are-poisoning-the-web/)，本轮继续关闭上游更新、可执行配置及浏览器远程脚本入口，并把旧部署文件检查接入发布流程。这里记录的是工作区中的实现和隔离测试，不是生产环境已经清理完成的证明。

配置仍使用 `<?php return [...]` 的历史存储格式，已有后台写入逻辑可继续工作；读取时仅视为数据。私有插件配置中的 `lang()`、常量、函数调用或其他表达式须迁移为字面量，把翻译与逻辑放回插件的受审源码。内置 AI 插件已完成迁移。非法配置会中止请求，这是有意保留的拒绝行为，发布前审计会先报告文件名。

## 浏览器策略与业务兼容

默认脚本来源为同源。确需自行管理的 HTTPS 静态域时，可在 `application/extra/maccms.php` 的 `app.security_script_sources` 配置精确 origin；不接受通配符、URL 路径、口令或已阻断域名。该选项不应作为恢复上游 CDN/JSONP 的入口。

为兼容现有 layui、内联事件及模板脚本，基线保留 `unsafe-inline` 和 `unsafe-eval`。因此它阻止未批准来源的脚本下载，不能代替 HTML 净化，也不能阻止所有内联 XSS、被篡改的同源脚本或所有数据外传。外部媒体、显式配置的业务 API 与跨域播放 iframe 仍各自需要信任审核；允许播放域不等于允许它在后台页面执行脚本。

原地图 SDK 改为地址或点击打开的地图链接；原远程动态表情改为本地静态 PNG；公式使用随代码分发的 SVG 字形包；图片压缩在主线程完成，大图可能短暂占用界面。已有数据库里的远程图片、统计字段和广告内容不会因模板更新而自动改变，须扫描导出并逐项核对。

## 生产验收入口

使用[部署与宿主机处置手册](../../security/supply-chain-deployment.md)生成可信源码基线，对站点文件、数据库导出和离线宿主机分别检查；使用[前端本地化记录](frontend-supply-chain-localization.md)核对功能变化、官方依赖来源及静态资产；Web 服务器配置方法见[静态 HTML 的 CSP](../../security/static-html-csp.md)。

本轮没有连接或修改生产站点，没有扫描生产数据库、宿主机磁盘、进程内存或 CDN 缓存。RingH23 的 udev、preload、Nginx 模块等持久化必须在可信救援环境检查；确认宿主机入侵后应保全证据并重建，恢复受审数据，从干净终端轮换凭据。源码扫描通过只能说明所覆盖规则没有发现，不能作为“所有未知后门均不存在”的承诺。
