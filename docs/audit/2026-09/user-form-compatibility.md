# 注册与找回密码表单的 PHP 8 兼容性

本批仅处理 `application/index/controller/User.php` 的 `regcheck`、`reg_msg`、`findpass`、`findpass_msg`、`findpass_reset`。共享用户模型的认证协议需要单独审计，本报告不代表完整账号恢复安全结论。

## 已确认的问题与修复

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| `regcheck` 未列入游客入口 | 未登录用户的注册预检查先跳到登录页，业务方法不可达 | 加入游客入口，保留真实模型的用户名、邮箱与验证码检查 |
| `regcheck` 直接读取 `t`、`str`，失败时返回用户输入字符串 | 缺参产生警告；数组产生类型错误；响应契约不稳定 | 限定支持的检查类型，拒绝非文本值，成功与失败均返回模型 JSON |
| 注册/找回验证码表单不提交 `code`，共享模型却直接读取 | 正常表单也产生 PHP 8 未定义键警告 | 入口补齐可选文本字段；合法目标继续走既有消息模型 |
| 重置密码表单仅提交 `to`，模型同时读取可选 `user_email` | 正常的重置表单产生警告 | 补齐可选字段，保留必需目标、验证码与原有密码校验 |
| 密保找回直接把缺字段与数组交给模型的 `trim` | 空表单和类型错误变成 PHP 8 异常 | 按实际字段建立文本参数；缺字段由既有校验返回错误 |
| `findpass_msg` 页面直接读取缺省 `ac`；默认模板还直接读取 `$_GET['ac']` | 无参数页面无法稳定渲染 | 缺渠道时重定向到明确的 `ac=email` URL；非法渠道受控拒绝 |
| `reg_msg` 接受 GET，`findpass_reset` 的 GET 无响应体 | 链接请求可能进入发送逻辑，错误调用得到空响应 | 两个动作只接受 POST，其他方法返回参数错误 |
| 注册消息的邮箱格式输入错误进入共享邮箱校验的 `explode` 缺项 | 普通输入错误变成警告 | 消息入口校验邮箱/手机号格式后再交给模型 |

参数入口只接收字符串或整数文本，不把数组、对象、布尔、浮点或显式 null 强行转成字符串。新增方法均为 private，不增加可调用的辅助路由。原有图形验证码调用、消息记录验证及用户查询继续由共享模型执行。

## 验证

`php -d error_reporting=E_ALL tests/framework_audit_user_forms.php`：PHP **8.3.33 / 8.4.25** 各 **288 项**通过。测试使用真实 TP8 默认路由解析、控制器构造函数和真实 User、Msg 模型/SQLite；仅基础页面渲染、验证码与发送服务使用明确 fixture。没有真实短信、邮件或外部认证请求，容器以 `--network none` 运行。

覆盖正常表单、已有用户/邮箱检查、游客可达性、缺字段、每个表单字段的类型错误、邮箱/手机双渠道、无可选 code/user_email 的正常请求、POST 约束。校验失败时断言密码和发送次数不变；正常密保与验证码重置仅更改隔离 SQLite 账号。

另外，通过既有 `tests/http_smoke.php` 在隔离 CI 数据库配置、只读代码与独立 runtime 中执行两版完整应用请求。每版 8 条 GET 路由验证：可用性预检查及空检查、密保表单、缺省渠道重定向、邮箱/手机表单、注册消息与重置接口的受控 GET 响应。该补充检查使用实际 Base、模板、应用引导和路由；没有执行真实发送。

## 后续独立问题

源码核对发现共享 `common/model/User.php::check_msg` 对消息记录的查询缺少接收目标条件，而 `findpass_reset` 同时使用 `to` 与 `user_email`；还需要单独审查消息绑定、用途、消费与重置目标是否一致。本批没有修改这些模型，也没有通过跨账号请求或恶意载荷验证。共享 `UserValidate::validateEmail` 的格式健壮性仍应在模型层统一处理，使其他调用入口受益。
