# 金融事务公共机制与返利故障复审

日期：2026-09-11。此批抽取既有购买事务机制，尚未接入返利或会员升级。

`FinancialTransaction` 承担原 PDO 身份、owner BEGIN / COMMIT / ROLLBACK、调用方私有 SAVEPOINT、确认后的层级恢复和未知结果上下文阻止。`PurchaseTransaction` 保留内容购买的构造合同、翻译及经过规范化的购买坐标。公共机制不读取模型、业务价格或返利配置；业务适配器在 BEGIN 前提供消息和有界诊断信息。

抽取后继续通过 PHP 8.3.33 / 8.4.25：每版默认金融套件 19 个进程零失败；owner 108、caller 127 项分别在 SQLite/MySQL 通过；原 MySQL 购买正常和并发 110 项。没有新建忽略规则或把验证借给尚未接入的金融路径。私有保存点采用统一 `mac_financial_` 前缀，故障夹具相应匹配实际 SQL；对外购买结果合同保持不变。

## 已确认的下一批问题

固定源 `de1d1a7d` 对 `User::reward` 的独立调查，使用真实 ORM/PDO 与隔离 SQLite/安装 MySQL。两版 PHP、两种数据库均观察到：

| 确认故障位置 | 原 PDO / 持久状态 | 当前结果 |
| --- | --- | --- |
| 独立 BEGIN 已执行后抛出 | PDO 仍活动，未写入返利，零次 rollback | 异常退出，事务未收尾 |
| 独立 COMMIT 已执行后抛出 | PDO 不活动，独立观察连接确认返利共 4 分已提交 | 仍抛出失败，不能据此再次发放 |
| 普通返利台账失败，rollback 在执行前反复拒绝 | PDO 仍活动，连接内已有 3 分返利及部分台账，观察连接尚不可见 | 清理异常退出，未完成回滚 |
| 调用方中嵌套完成后抛出 | 随后的 rollback 结束外层，调用方普通标记消失 | 破坏调用方事务边界 |

这些是直接返利调用的证据。F1b 购买作用域能够隔离其内层返利异常，不代表返利本身的 owner / caller 合同正确。当前应用的直接返利调用位于 ContentPurchase 和 User::applyMembershipUpgrade；后者和 Order::notify 的外层收尾需一起明确错误传播，不能把内部未知结果吞成普通失败后继续提交。
