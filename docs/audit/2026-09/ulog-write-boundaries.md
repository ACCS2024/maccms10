# 用户行为与购买记录写入边界

`Ulog::saveData` 原来把调用端已经校验的会员编号覆盖为 `cookie('user_id')`，使 Bearer 登录和混合凭据请求无法可靠地把记录保存给实际身份；同一方法还允许凭 `ulog_id` 更新记录，更新条件没有用户归属。本组删除模型内的 Cookie 身份推断，要求调用端明确传入已经验证的 `user_id`，只允许追加记录，拒绝携带 `ulog_id` 的更新请求。当前四个实际写入调用端均自行构造字段并传入认证后的编号。

允许的模型和操作组合为视频收藏/历史/播放/下载，文章与漫画阅读/收藏/历史，专题与角色收藏/历史。编号与积分只接受十进制整数或整数字符串；不把数组、浮点数、负值、科学计数法和空值转换为有效字段。存储层验证实际启用的会员存在，使用明确字段列表和服务器时间；客户端附加字段不会写入。

安装 DDL 中 `ulog_sid` 为 TINYINT UNSIGNED，`ulog_nid` 和 `ulog_points` 为 SMALLINT UNSIGNED，因此本组分别限制到 255、65535、65535。资源编号和会员编号保持 INT UNSIGNED 范围。需要超过这些容量的内容库必须先独立扩容数据库，不能靠截断记录继续扣费。该边界不会自动改动生产数据库或修复已有截断记录。

写入使用事务并逐字段读回确认，MySQL 非严格模式下遇到历史更窄字段或数据库触发器改变数据时，失败记录会回滚。MySQL 表必须是 InnoDB，SQLite 支持，其他驱动受控拒绝。已有外层事务仍持有最终提交权；保存方法内部提交不会使购买扣款事务提前生效。异常返回既有失败码，不暴露数据库异常内容。

验证：`php tests/framework_audit_ulog_writes.php` 使用从安装 SQL 提取的真实结构、独立测试会员和记录；SQLite 114 项、MySQL 非严格模式 115 项在 PHP 8.3/8.4 通过。覆盖实际归属、合法行为组合、类型与字段宽度、不可更新旧凭证、外层余额/记录回滚、静默截断和存储故障。MySQL 仅使用 `maccms_audit_models` 的 `audit_ulog_write_` 表，已纳入 `models` 套件。

本组是存储边界修复。前台/API 重复购买实现的事务内重复检查、积分账本与奖励失败传播、真实章节与价格解析，以及购买凭证删除/隐藏策略仍须由紧接的购买链批次完成；此处不宣称完整购买流程已经安全。零额普通行为记录本身不能命中目前要求价格精确相等的正价播放授权查询，不能据此推断已经存在正价付费绕过。
