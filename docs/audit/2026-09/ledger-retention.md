# 保留原始账变，会员侧隐藏记录

旧会员/API 与后台接口会物理删除 `plog`，`saveData(plog_id)` 和 `fieldData()` 还能改写已有账变。删除会改变后台按账变计算的统计，原始支付/消费证据也随之丢失。商业版默认保留原始账变；本次没有恢复已经删除的历史记录。

## 行为

- 正常账变继续追加；通过普通模型接口修改、删除原始记录均受控拒绝。后台保留查阅/统计，删除和清空操作移除。会员隐藏的记录在后台仍可对账。
- 会员按钮及确认文案改为“隐藏/隐藏全部”，原有接口路径保留，接口仅设置所属记录的 `plog_user_hidden=1`，不改变原始金额、积分、时间、类型、备注、账号或余额。API 与页面列表/计数/筛选/分页只展示未隐藏记录。反复隐藏是幂等操作。
- POST、正整数 ID 上限及用户归属由实际请求与模型两层限制。只能明确 `all=1` 隐藏自己全部记录；未传/畸形列表不会扩大范围。Ulog 的收藏/播放历史仍按原设计删除，金融留存针对 Plog。
- 没有新列的旧库仍可读取和追加账变；隐藏返回明确的升级未完成错误，绝不降级为物理删除。迁移完成后无需手工修改用户记录。

## 旧库迁移

新安装 SQL 包含 `plog_user_hidden TINYINT UNSIGNED NOT NULL DEFAULT 0` 和 `(user_id,plog_user_hidden,plog_id)` 索引。旧库使用独立 CLI，不加载应用、不自动读取 `.env`：

```sh
# 由部署环境显式提供 LEDGER_SCHEMA_DSN/USER/PASSWORD，及可选 PREFIX（默认 mac_）。
php migration/preserve-ledger-records.php
# 完成备份、检查上条输出，并在维护窗口执行：
php migration/preserve-ledger-records.php --apply
```

默认只执行 SELECT 预检。报告列出新增列/索引；不存在或非 InnoDB 表、必要列缺失、同名不兼容列/索引及异常隐藏值都会阻止自动执行，不覆盖这些结构或数据。`--apply` 会重新预检并执行 DDL，重复执行无额外变化。DDL 可能等待元数据锁或重建索引，应在测试副本评估时长；已有长驻进程/字段缓存需在迁移后重新加载。

迁移只添加显示状态和索引，不删除或重写原始财务字段。已经删除的记录不会凭空恢复；数据库备份或其他账务证据需要另行对账。

## 验证与范围

`security_audit_ledger_retention.php` 使用真实 Plog、会员/API 动作和 ORM，认证与展示辅助函数隔离；双 PHP × SQLite/MySQL 各 47 项，验证原记录逐字段保持、金额总量与用户余额保持、隐藏归属/幂等、会员计数分页、后台可见性、拒绝原始修改/删除和旧库兼容。

`security_audit_ledger_schema.php` 在专用 MySQL 上各 23 项，包含实际安装 DDL、只读事务中的 preflight、真实 CLI 默认不改库、显式迁移/幂等、冲突结构和异常值阻断。MySQL 始终使用 `maccms_audit_membership` 的 audit 表，与其他 financial 测试串行。

`ledger_http_smoke.py` 通过实际会员/管理员登录验证 37 项 HTTP 断言；PHP 8.3/8.4 的开发服务器与生产 Apache 四组合均通过，含会员隐藏后后台真实行仍可见、删除拒绝、原始字段/余额保持。32 个后台页面在四组合均正常渲染。

回归种子增加了非空账变和对应测试余额，后台模板不再被空表掩盖。原删除选择、列表、支付、会员、卡密回归继续执行。

这是应用普通接口的留存规则，并非数据库层不可篡改存储。拥有数据库管理或任意代码执行权限的人仍可改表；管理员手工余额调整、外部业务对账、审计日志备份/权限分离和灾备恢复仍需完整运营设计。本组未部署或运行生产迁移。
