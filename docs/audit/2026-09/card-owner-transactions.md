# 卡密充值事务与落库（F3a）

日期：2026-09-11。固定源 `f32e4000` 的两版 PHP、SQLite/MySQL 共 18 条普通故障观察确认：BEGIN 已执行后异常逃逸且 PDO 活动；COMMIT 已执行后仍返回普通 1004；rollback 持续拒绝时卡片已认领、积分已增加但事务仍待提交；嵌套完成后异常触发外层回滚并丢失调用方标记。缩小 MySQL 台账列的非严格夹具中，300 分台账存为 255 仍报告成功；这属于存储容量不一致条件，并非声称新安装默认 Card/Plog 列就存在该容量差异。

CardTransaction 接入共享原 PDO 拥有者机制。当前两处应用调用者（API Payment 和前台 User）均直接兑换，未包裹外层事务；已有原生或 ORM 调用方事务在写入前受控拒绝。真实 Card/User/Plog 表必须支持事务，BEGIN 纳入保护，未知提交或无法确认的回滚带诊断编号并阻止当前上下文继续金融操作。诊断信息只含用户 ID、卡片 ID 和积分，不包含卡号、密码。

锁定主库当前卡片与用户，核对余额上限。认领和入账后核对实际卡片身份/面值/状态/使用者/时间、余额、充值台账用户/类型/积分/备注，任一存储值改变即整笔回滚；普通错误仍保留原 1002/1004 合同。先限制 UTF-8 最大字节数，再执行字符校验，保持卡号 16 字符、密码 8 字符合同。

PHP 8.3.33 / 8.4.25 各完成：改动 PHP 编译；金融套件 23 个进程零失败；新增 owner/存储检查 SQLite 80 / MySQL 非严格模式 84 项；原兑换业务 SQLite/MySQL 各 25 项。覆盖实际 ORM/PDO 确认前后故障、独立观察连接、有限回滚、原调用方保护、跨业务阻止、13 个普通存储变更触发器、三张非事务表与台账截断。原并发 winner 夹具移到实际 Connection BEGIN 前，确认同一卡不会被两个用户重复兑换。

持久入口 `tests/framework_audit_card_owner.php` 已加入金融套件；隔离 SQLite 文件与 `maccms_audit_card_owner` MySQL 数据库只用于审计。原始证据在 `/tmp/maccms-audit-20260910/card-followups/` 的四份固定源观察、`check1.log` 和 `validated-tree.txt`。本批通过数据不能替代 `f32e4000` 的完整快照记录，也不借用订单并发子进程检查声称卡密已覆盖全部并发故障。
