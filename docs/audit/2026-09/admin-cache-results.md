# 后台缓存清理的授权与结果

`index/clear` 现在要求原始和有效方法均为 POST，重新核验当前管理员状态和 `index/clear` 权限，并强制验证会话 CSRF。该要求不受旧的全局关闭或豁免配置影响。现有后台按钮已通过 jQuery POST 发送 `X-CSRF-Token`，可继续使用。内部 `_cache_clear` 改为 protected，禁止通过继承的公开动作绕过入口。

播放器配置生成失败直接结束；运行目录和缓存驱动分别核验实际结果，任何失败都返回错误，AJAX 不再从 error() 返回后继续执行成功分支。清理根符号链接或误配置目录时保留目标并报告失败。后台缓存按钮保留 runtime/log；确需维护日志时使用带显式 `--with-log` 的 CLI 清理。

原“强制”搜索清理仍附带过期时间条件，近期搜索结果和演员查询可能残留。后台改用独立的 `VodSearch::clearAllResults()`，清理全部搜索缓存行并重置本进程查询 memo；周期过期维护方法保留原有用途。数据库异常返回失败，恢复后可以明确重试。操作跨文件、缓存服务和数据库，不构成一个事务；失败可能发生在部分缓存已清理之后，不声称全部回滚。

PHP 8.3.33、8.4.25 在 SQLite、真实 MySQL 各通过 63 项检查，使用真实管理员构造、路由、会话、最新权限、安装表结构及 ORM。覆盖非法方法/覆盖、缺少或错误令牌、权限撤销、构造后身份变化、重复清理、普通播放器生成、日志保留、根链接、缓存 false/Exception/Error、实际数据库拒绝删除和恢复。默认回归入口同时包含新测试。

使用独立 `maccms_audit_admin_cache` 测试数据库。未连接生产站点或缓存。缓存驱动的清理范围仍取决于已选后端；Redis 整库清理与共享会话/锁的隔离需要另做配置和命名空间治理。网页初始化的历史自动迁移、周期搜索维护的节流和并发更新也仍在复审清单中。
