# 播放器配置缓存完整替换

后台重新生成播放器列表时，原逻辑直接以 `wb` 打开正式文件，忽略写入结果；打开失败还可能把 false 传入 `fwrite()`，在 PHP 8 下触发 TypeError。现在先验证三组列表和缓存标记，再在同目录独占创建随机临时文件，完整写入、刷新并同步，最后 rename 替换正式文件。数据或文件条件不满足时返回 false，保留正式文件；后台清理结果的传播与请求校验在后续独立批次处理。

保留缓存区之外的字节内容；正式文件不存在时仅允许从普通 `.bak` 文件恢复。禁止目标文件、备份、受管 static/js 目录使用符号链接。编码验证 UTF-8 并转义 JSON 字符，空列表输出对象；允许旧配置省略 des、ps、parse，拒绝缺少 show 或结构异常。每组最多 4096 项、单字段最多 65536 字节、三组键值原文共 1 MiB、输入和最终 JS 文件各最多 8 MiB。异常不包含配置内容。

PHP 8.3.33、8.4.25 各执行 58 项普通检查、非特权账户下 61 项检查，覆盖普通配置、字节保留、合法旧字段默认值、结构和大小限制、JSON 解码、错误标记、备份恢复、链接与真实目录写权限失败。修复权限后可重试，没有遗留临时文件。

临时文件与正式文件位于同一目录，解决普通写入失败造成的截断；发布前检查源内容未变化。这不是跨多个独立配置写入者的事务协议，仍不保证抵抗拥有目录写权限的进程并发替换路径，也未验证 Windows 原生发布行为。
