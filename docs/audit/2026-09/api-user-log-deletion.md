# API 用户行为记录删除边界

`api.php/user/del_ulog` 原先接受 GET，并把 `ids`、`type` 等直接交给字符串转换和整数转换；数组可触发 PHP 8 错误，`1x` 或负数等畸形值会被当作实际记录 ID。它与已修复的前台入口使用不同实现，原测试未覆盖这个 API 路径。

现在要求 POST，只读取请求体，使用共享的有界正整数选择器；始终限定已认证用户。单选/多选保留 `ids` 和旧 `ulog_id` 别名，传入 type 时一并限定类型；明确 `all=1` 必须提供合法类型，缺值或畸形输入不会扩大删除范围。收藏/播放历史仍按既有设计物理删除，账变的隐藏留存另由 Plog 处理。

扩展 `security_audit_user_log_delete.php` 覆盖两个前台动作和 API 动作，使用实际 Request、控制器和 ORM，隔离认证/展示。验证跨账号保留、类型范围、全部清理、数组/非法数字/超长列表、GET 拒绝、旧参数别名及未认证拒绝；会员认证本身由真实会话与 HTTP 回归覆盖。
