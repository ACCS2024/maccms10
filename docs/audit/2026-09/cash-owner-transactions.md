# 提现申请、退款与审核的事务收尾

三个入口原来在异常处理外执行 BEGIN，异常后直接再次回滚，并把提交丢确认归为普通失败。现使用共享原 PDO 事务机制：拒绝已有调用方事务和非 InnoDB 参与表，BEGIN 进入有限清理，只有确认提交后返回成功。未知提交/回滚结果含核查编号和 `retryable=false`，并阻止同请求再次申请、退款或审核。所有读写和回读明确使用当前主库。

本批保持已存在的冻结积分、退款容量和审核台账合同，保留已完成操作的合法重复返回。数据库写入使用服务端构造的明确字段，不再借用另一条模型元数据查询过滤提现字段。金额输入精确性、全字段实际存储核验、持久幂等和核对仍需后续独立批次。

`framework_audit_cash_owner.php` 对三类操作分别验证 ORM/PDO BEGIN、ROLLBACK、COMMIT 前后故障、清理无法确认及外层事务保全，通过第二连接核对实际余额、冻结积分、提现记录与台账；MySQL 另验证逐表非事务存储拒绝。旧退款回归的并发插入点调整到实际连接 BEGIN 之前，保持普通竞争结果和真实 MySQL 锁验证。专项已加入 financial 套件。
