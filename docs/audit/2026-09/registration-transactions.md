# 注册、验证码与邀请奖励事务（R2）

## 本组行为

`User::register` 在所有输入和奖励配置通过校验后，使用同一写连接事务完成验证码消费、新账号创建、初始积分及账本、推荐关系、邀请计数、直接推荐积分和阶梯奖励。任何一项失败，所有业务表恢复到提交前状态；合法表单和验证码可在故障解除后重试。注册初始化使用启用且实际存在的会员组，组编号遵循安装 DDL 的有符号 SMALLINT 上限 32767。

验证码始终使用游客 `user_id=0`、实际渠道/收件人、注册用途 `msg_type=3`、有效时间和未消费状态，即使浏览器带已有账号的登录状态，发送和校验也采用相同作用域。联系方式不能覆盖其他账号已有绑定。正常邮箱/手机号注册仍先通过已有发送入口取得验证码；测试使用隔离发送函数，无外部邮件、短信或真实账号。

API 注册只接受 POST 正文。网页注册只从 POST 正文读取账号和密码，正文未指定推荐人时才采用经过严格校验的既有推荐 Cookie。GET 邀请链接只接受有效 uid/邀请码；不会把未校验值直接传入模板。需后台审核的注册返回创建成功和 `pending_approval=1`，避免账号已经创建却显示自动登录失败。

## 积分和一次性来源

初始积分从零开始通过 `PointsBalance` 入账。每一笔注册赠分、直接推荐和阶梯奖励均写入 `plog_type=2` 收入账本，并读回验证余额与账本字段；历史类型 8 记录保持原样。多个新跨越阶梯使用累计状态计算，较低会员组不会覆盖刚发放的更高会员组，期限逐级累计，积分/计数/期限溢出均拒绝并回滚。

公共兼容包装 `addInviteCount(parent, source)` 需要当前模型实例刚 INSERT 的私有来源上下文。包装进入时立即消费上下文，锁定真实来源与推荐账号并核对 `source.user_pid=parent`；普通调用、既有账号或只有历史推荐关系均不能触发奖励。`processInviteReward` 同样只允许由当前邀请事件内部继续调用。

持久凭证是新账号自身账本中的固定零额记录：`user_id=source`、`plog_type=2`、`plog_points=0`、备注 `注册推荐确认：<parent>`。查询限定来源账号、类型和固定内部前缀，不接受客户端备注，不依赖安装表中有符号的 `user_id_1`。即使全部奖励为零，凭证与计数也必须提交。该零额凭证会显示在新账号的账本中；零额注册/直接推荐账本同样可见。无私有新建上下文的历史账号不能因缺少凭证而被重新奖励。

## 锁与旧安装边界

MySQL 在事务前按固定顺序获取注册邀请码池、用户名、可选 IP 额度、可信 OAuth 标识、联系方式的命名锁，之后才获取账号行锁和消费消息。联系方式使用与绑定完全相同的 `acquireContactLock(channel, recipient)` 名称。注册不会在持有账号行锁时再申请命名锁；绑定只在取得联系方式锁后锁账号，密码重置在账号锁后更新消息，因此这些路径不存在反向等待注册命名锁的环。锁等待超过 5 秒返回受控失败，业务状态不变，可重试。

默认安装尚无全套身份唯一索引，注册邀请码池锁暂时串行化这一入口的短写事务；密码计算在锁外执行。用户名/联系方式/邀请码可用性和 IP 当日额度在取得锁后重新读取写库，邀请码生成有界且不存在未经复核的回退候选。邀请码重复历史记录、不可用推荐人或异常推荐层级会拒绝注册。

这不是全表唯一性的替代：后台新增/编辑、历史 `generateUniqueInviteCode` 写入和尚未统一的自动注册入口没有全部采用这些锁。部署迁移仍需扫描重复用户名、联系方式和邀请码，处理旧数据后增加相应数据库约束；高并发部署应完成该迁移后再消除邀请码池串行瓶颈。本组不宣称所有账号写入入口具有统一唯一性保证。

User、Msg、Plog、Group 任一表为 MyISAM 或其他非 InnoDB 引擎时，MySQL 注册受控拒绝。SQLite 用事务验证，其他数据库类型拒绝。写入成功还要读回关键账号和账本字段，发现旧窄字段在 MySQL 非严格模式下静默截断时回滚，不能把 affected rows 当作完整保存证据。

## 验证

新增 `tests/framework_audit_registration_transactions.php`，复用从安装 SQL 提取的 User/Msg/Plog/Group DDL。SQLite 验证正常注册、真实路由、原始密码、验证码作用域及消费、推荐凭证、累计阶梯、配置/溢出边界和各阶段触发器故障。MySQL 使用专用 `maccms_audit_user_registration` 数据库、非严格模式，额外验证 4 表非事务引擎、9 种窄字段截断、独立连接锁超时，以及独立 PHP 进程下的同名、IP 额度、同联系方式、跨阶梯、注册与绑定/密码重置竞争。

每个并发进程校验实际读取配置与父测试场景一致；并发断言检查成功次数、账号数、邀请码计数、验证码状态、实际余额和重置后的密码/会话随机数。没有调用真实发送服务、外部身份服务或生产配置。

既有注册输入、消息匹配、表单、绑定和 OAuth 边界回归一并运行。最终 PHP 8.3/8.4 与 SQLite/MySQL 检查数见本次冻结清单。

## 紧接的后续组

`loginOrRegister` 本组仅调整新建来源凭证调用、删除现在由邀请包装负责的重复直接加分，并传播失败；其外层账号创建和自动登录仍未统一为本组完整事务，失败可能留下刚创建的账号，不能作为最终交付残留。下一组应立即统一其输入/配置/挑战来源、注册原子性及会话契约。后台/OAuth 其他独立身份写入与唯一性迁移另行收口。
