# 跨模块复审清单

日期：2026-09-10。此表记录分批修复中发现的共同根因，避免把一个入口通过回归误当成整个系统已解决。实施中的批次仍须独立冻结、测试和提交；未列为完成的项目不是上线验收通过项。

| 类别 | 已取得的证据 | 后续边界 |
| --- | --- | --- |
| Collection 与旧数组合同 | 搜索建议丢弃合法行；后台 CSV/XLSX 下载实际 TypeError，分别已修复。统一 Search 的同类丢行正在独立处理 | 继续核对更严格静态扫描中的真实调用，不把 PHPDoc 推导出的数组类型误判成运行时类型声明 |
| 主从延迟、连接切换与元数据 | Cookie/JWT 已改主库核验；手工附件已验证主库实际 InnoDB；文章购买已证明隐藏在 reader 后的 caller raw master 事务保持完整 | Search 正在检查主库 schema 与主库行。共享 PublicContentQuery、单模块建议、Group cache 与其它读取仍要独立复审；给业务查询加 master 不会自动改变另一次元数据查询 |
| 资源授权的实际坐标 | 视频、文章已统一实际资源与阅读规则。漫画真实诊断确认缺章收费、密码未执行、旧缓存绕过状态、非连续章导航错误 | 漫画解析、读取授权、锁内购买分开提交；模型不再报错不代表原来被错误掩盖的访问缺口已关闭，见[漫画计划](manga-resource-access-plan.md) |
| 外部对象与数据库引用 | 手工附件/头像已登记全部衍生文件、持久意图、精确引用并延后本地清理 | 图片下载、AI 封面、Collect/Images 资源绑定、Annex 主动删除、目标迁移仍分别需要证据，不能沿用“SDK 返回成功就可删源文件”的假设 |
| AI 封面并发与恢复 | 双 PHP 隔离复现：目标 Vod 删除后仍成功、覆盖并发编辑、DB 拒写前源文件已删、未统一解码、还原主图后保留 AI 缩略图 | 生成需要当前资源行与 Annex/Intent 同事务；还原旧缩略图需要可靠历史备份，不能凭空恢复。缓存更新失败与已提交业务结果应区分 |
| 回滚自身失败 | ContentPurchase 的 catch 仍直接调用 Db::rollback；原触发器测试只证明回滚正常时的行为 | 补回滚前/后异常、断连接、提交回执未知，以及普通 buy 的 caller 外层事务；不能盲目直接回滚底层 PDO 而结束调用者事务 |
| 旧数据库返回值判断 | level 5 多处指出 ORM 的 int 返回值不可能严格等于 false；AI 封面零影响行伪成功已有真实证据 | 分清插入失败、对象已删除、正常幂等更新与异常抛出，逐条验证写入合同；不能全局把 `=== false` 替换成 `=== 0`，否则未改变字段的合法保存也会被误报失败 |
| 网页中的隐式 DDL | Manga::infoData 即使 cache=0 仍调用 ensureRecycleColumnExists；后台初始化也有自动迁移入口 | 独立设计安装/升级前置条件、显式迁移及缺列受控行为，保留已有数据；不直接删共享 trait 使旧站升级失效 |
| 导出格式安全与资源消耗 | 本轮导出只证明真实下载、筛选/数量和 CSV/XLSX 字符保真 | CSV 公式单元格策略、导入往返合同、XLSX 大单元格预算仍待专项审计，不能用语法或文件格式有效性代替这些结论 |
| 自动完成组件合同 | 已修复的建议 DTO 使用 name，而 static/js/home.js 的 formatResult 读取 text；同段展示和选择使用 name | 实际组件输入/选择回归后按精确函数修改；旧主题重复实现、打包脚本及未合并前端资源修改需分别核对 |
| 配置解析资源上限 | 对未合并的 DataConfig 候选实现预审：token 数量限制在 token_get_all 之后。双 PHP、128M memory_limit 下，约 1 MiB 的短数字数组在计数前耗尽内存；约 512 KiB 才能正常走 token 上限拒绝 | 配置作为数据读取的方向不能只验证“未执行 PHP”；还须在分词分配前约束资源，同时保留合法大字符串配置和 var_export 兼容性。此候选尚未作为通过审计的配置加载链提交 |

AI/下载证据位于本次隔离工作目录 `remote-download-survey`，双版各 10 项，不连接真实供应商。DataConfig 证据位于 `data-config-review/token-memory.log`，使用内存受限且无网络的容器；只解析数组文本，没有执行待解析文本。未知结果的远端对象、旧文件与生产数据均未清理。

当前扫描结果仍需按“静态候选 → 实际复现 → 最小修复 → 相关正常/失败回归 → 独立提交”处理。固定快照的完整编译与扫描范围见[阶段验证记录](phase-verification-cdc213f.md)；不能把那份快照的数字直接当作后续未合并代码的验证结果。
