# 配置数据解析器与分词前资源预算

日期：2026-09-10。本批只交付 `DataConfig` 工具、独立测试及 CI；配置加载器的接入属于后续批次，不能据此认为全站已经停止执行配置文件。

工具读取本地普通文件，把 `return` 数组解析成数据，不包含文件、不求值、不启动应用。支持 `var_export` 输出、字符串键和整数键、有限数值、布尔、null、嵌套数组、注释、单/双引号字面量及字面字符串拼接。NUL 与全部字节的 `var_export` 往返、Unicode 转义、十六/八/二进制整数及最小平台整数均有独立检查。变量、函数、常量引用、插值、额外语句与不支持的表达式受控拒绝。不存在的可选文件返回空数组；链接、目录和 URL 包装器不作为配置文件读取。

原候选实现虽有 8MiB 字节上限，但在 `token_get_all` 已经分配全部 token 后才检查 50 万个 token。双 PHP、128M 限制下，约 1MiB 的普通短数字数组在计数前耗尽内存。仅在分词后增加计数不能防止这一失败。

现在先做单遍词法预算检查，再调用原生分词器校验 PHP 语法。完整字符串和注释按各自上下文跳过，不把其中的字符误算成大量代码 token；不支持的词法结构、超深结构和超预算输入在原生分词前拒绝。8MiB 字节上限保留，保守 token 预算设为 10 万；随后仍核对真实 token 数量。解析保留原 64 层值嵌套合同，最深处的空数组兼容性单独验证。整数最大键后的自动追加也改为受控错误。

独立测试只创建普通临时配置和不可执行的解析输入，不读站点配置、不加载其它候选改动。`python3 tests/run_data_config_parser_audit.py` 在 PHP 8.3.33 / 8.4.25 各运行 12 个独立进程、101 项检查，使用 `php -n`、128M 内存限制和隔离网络。分词探针只计数，实际调用原生 `token_get_all`。

| 正常或边界配置 | 实测结果（双版本） |
| --- | --- |
| 33,331 个短整数 | 完整保留，峰值 16.01MiB；再加一项在分词前拒绝 |
| 约 1MiB 密集数组 | 原生分词调用为零，受控拒绝，峰值 4MiB |
| 总源文件恰好 8MiB 的单字符串 | 完整保留，峰值 34.01MiB |
| 7MiB 字符串加 30,000 个整数 | 完整保留，峰值 40.12MiB |
| 接近 8MiB 的转义字符串 | 完整解码，峰值 34MiB |
| 接近 8MiB 的单条注释 | 正常解析，峰值 26.01MiB |

峰值来自隔离工具进程，不能当作带框架、其它配置和业务对象的全请求内存保证。后续接入必须核对所有现有配置文件格式、读取错误的业务处理、写入原子性和部署资源预算，不能直接把尚未验收的配置加载链一并提交。本批也不以解析器存在代替依赖来源或恶意文件全量审计。
