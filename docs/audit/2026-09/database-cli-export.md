# 数据库备份 C1：CLI 导出原子产物与 InnoDB 一致读

范围为 `application/common/util/DbBackup.php` 的导出与表列表，以及 `application/command/DbExport.php` 的必要调用方契约；CLI 恢复解析留待 C2，不改 A/B 控制器与编解码工具。

原实现先用 `fopen(..., 'w')` 截断目标，再读取表结构；真实 MySQL 不存在表错误会破坏上一份有效产物。多个写入返回值未检查，数据库异常也没有统一关闭/清理。独立的旧序列化器还遗漏生成列、BIT 和浮点精度等 A 组已验证的边界。

现在先校验目标是普通文件路径、表选择是当前库的普通表，再进入同目录私有暂存区，复用 A 编解码器导出。目标文件在完整写入、复制、刷新、关闭检查通过后才通过 rename 替换，失败保留原产物；新文件权限为 0600。数据预处理和完整文件复制均避免读入整个导出文件。默认表列表只列普通表，显式选择视图会拒绝，避免生成无法恢复的 DROP TABLE/CREATE VIEW 混合产物。

导出使用 ORM 管理的只读 REPEATABLE READ 事务：计数及各表所有分页共享第一次一致读的快照，ORM 的事务计数同时保护连接路由及重连错误路径。已有调用方事务时拒绝导出，不提交或回滚调用方工作。所有选定表为 InnoDB 时返回 `consistent_snapshot=true`；MyISAM 等表继续支持导出但返回 false，不宣称它们受事务快照保护。独立 SQL 文件保存/恢复 SQL mode 和外键检查，保留自增列显式零值。CLI 普通输出说明非 InnoDB 的维护窗口条件，porcelain 仍只输出文件路径；显式 `--tables` 可用于未配置前缀的连接，但缺少前缀且没有明确选表时继续拒绝导出全库。

`python3 tests/run_cli_export_audit.py` 在无网络 PHP/MySQL 容器中创建随机专用库。PHP 8.3.33 / 8.4.25 各 **48 项真实检查通过**：包括第二真实 PDO 连接在首表查询后事务更新两表，导出恢复后两表仍为同一更新前版本；1005 行分页、空表、NULL/CRLF/二进制/JSON/精确数值/生成列/自增零值、已有事务保护、旧 CLI importer 兼容，以及 copy/write/rename 故障时保留原文件并释放资源。另外使用真实 Command/Input/Output 验证成功状态、失败非零状态与旧产物保留、非 InnoDB 提示、porcelain、空前缀安全默认、显式选表及合法表名 `0`。测试只读取固定代码与自身生成的临时 SQL，不加载站点配置或真实备份。

边界：单批最多 1000 行、单条语句仍可很大，不是严格按字节限内存；数据快照不等于跨数据库/外部服务一致性，备份期间也应避免 schema 变更。非事务表仍须暂停写入的维护窗口。长只读事务会延长快照存活，不能把当前开发/测试 CLI 当作无限规模的运维备份平台。原子 rename 只保证发布完整文件，不宣称目录 fsync 或断电恢复保证；强杀可能留下隐藏暂存目录。CLI 与后台控制器没有共享任务锁，调用方应为并发任务使用独立目标文件名。恢复中的通用 SQL 分句、前缀改写及失败状态恢复仍由下一 C2 组解决。
