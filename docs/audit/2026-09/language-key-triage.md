# 语言键覆盖分类与无语义变化清理

本组以 `d5e4f5d` 静态结果的 643 条 `array.duplicateKey` 为线索，对当前九个全局语言文件做只读 token 分析。未 include 或 eval 待审计语言文件；`tools/audit/language_keys.php` 只接受一个返回平面字面量数组的文件，不支持的表达式、转义或额外代码直接报未完成。

原始 28,457 条声明中，627 个重复键的所有值完全相同，另有 16 个键有不同文案。前者含 629 条冗余声明；清理仅删除后续同值声明，保留第一次出现的位置。清理前后九个最终键值数组的序列化 SHA-256 全部相同，连键的插入顺序都未改变。当前保留 27,828 条声明、16 个冲突键，不按重复次数把它们计成安全漏洞。

## 逐条冲突处置

PHP 当前取最后声明的值，本组不改变这些值。

- 九种语言 `menu/configuser`：旧会员参数配置改称会员互动/社区；需单独选择和维护菜单文案。
- 德语 `menu/manga_data_points`：两种“漫画需要积分”的表述，现值保留。
- 简体中文 `website`（网址→网站）、`type_id`（分类编号→分类ID）、`total`（总共→总集数）、`data`（条→数据）：属于不同上下文共用键，后续应检查调用位置，不能凭顺序猜测正确翻译。
- 简体中文 `admin/upload/test_write_ok`：成功文案被失败文案覆盖。已定位后台 Upload::test 成功分支使用此键，失败分支却使用缺失的 `test_write_err`；其他语言也沿用了错误的成功键值。已确认需单独修复双分支反馈。
- 简体中文 `api/require_comment_name`：昵称提示被正文提示覆盖；Receive 实际两个不同字段也都引用 name 键。已确认应分开昵称与正文提示，按错误码保留 API 合同。

## 复验

```sh
php tools/audit/language_keys.php > /tmp/language-keys.json
```

返回 0 表示无重复，1 表示完整分析后仍有重复需分类，2 表示语法或读取限制导致未完成。报告含文件 SHA-256、最终键值及顺序的 SHA-256、冲突位置和全部对应字面值；不自动修改文件。双版本编译和 token 报告验证之外，本组没有把翻译清理当成业务安全回归或完整站点验收。

阶段原始证据位于 `/tmp/maccms-audit-20260910/language-keys-before.json`、`language-keys-after.json`，工具及处置规则存于仓库用于复现。

## 已确认文案错误的独立修复

后续文案组已将九种语言的上传测试成功/失败分别放入 `test_write_ok` / `test_write_err`，后台既有两个分支无需修改；成功不再显示失败提示，失败也不再显示未翻译键名。接收评论接口把昵称/正文校验分别指向 `require_comment_name` / `require_comment_content`，保留错误码 2001/2002，并补齐九种语言清晰的提示。

这解决上述两个已确认的冲突根因，保留其他 14 个冲突键继续按上下文分类。默认和自定义主题无需改键；其他调用者未出现对新键的旧依赖。双版本编译、语言 token 扫描与既有 Receive 输入回归复核；本组为低影响文案修复，没有新增镜像实现逻辑的单元测试。
