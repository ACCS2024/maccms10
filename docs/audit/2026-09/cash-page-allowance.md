# 提现页展示与异常配置

两套会员提现页面不再直接用模板中的余额除以兑换比例。配置为 0、缺少配置或错误的数组类型时，原运算可能触发 PHP 8 异常；当前比例也不能准确表示历史冻结申请的金额。

页面现在展示可用积分、冻结积分及单笔最多可申请金额，并明确积分向上取整。`CashView` 通过实际提现扣分规则查找可支付金额，受可用余额、65,535 积分单笔存储上限及金额容量约束，全程使用整数分。未知余额/比例显示 `--`，余额为零正常显示 0，功能关闭或达不到最低金额时显示单笔可申请 0.00 元。真正提交时仍由事务内模型重新核验余额与规则。

回归以真实模板引擎渲染默认及旧主题的完整提现页（只隔离公共 include），覆盖有效、零值、缺键和错误类型，检查发布脚本、账号范围的待确认编号存储和会话令牌 URL 连接。极小比例、八位比例、整数及金额上限还验证“展示上限可支付，增加一分即不可支付”。
