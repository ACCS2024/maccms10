# 用户验证码的匹配与发送契约

本批限定共享 User 模型的验证码校验、下发和邮箱名单校验，密码重置与绑定/注册的事务消费另行提交。

- 校验同时匹配收件人、用途、所属用户、六位验证码、未使用状态与有效时间范围，拒绝未来时间记录。以前查询缺少收件人与状态条件。
- HTTP 文本不再重复 URL 解码或 HTML 编码，包含 `+` 的合法邮箱与后续账号字段保持一致。注册按配置要求的邮箱/手机渠道核验，绑定保存已核验的规范化收件人。
- 参数严格区分文本与结构值；收件人遵守当前 `msg_to varchar(30)` 的容量，避免旧非严格 MySQL 静默截断。更长邮箱需要先统一升级用户及消息字段，此批没有擅自变更安装库。
- 验证码用 `random_int` 生成。下发不要求尚未生成的 code；保留发送限流和重发间隔，配送失败、异常或记录失败均返回受控错误。消息记录保存去标签后的最多255字符摘要，不把过长邮件模板写入短字段。
- 邮箱先做格式检查，名单按不区分大小写的域名匹配，错误配置受控失败。邮箱有效期取配置的1～1440分钟，配置无效时使用5分钟；手机仍为5分钟。

PHP 8.3.33 / 8.4.25 各94项真实 User/Msg ORM SQLite 检查通过，覆盖两种渠道及三种用途、有效期、匹配条件、参数类型、记录失败与配送失败。原288项表单/路由检查同时通过。所有配送为明确的内存fixture，没有发出真实短信或邮件。SQLite验证不代表线上旧MyISAM数据库具备事务能力。
