# 导入列映射（I1c）

日期：2026-09-11，固定问题源 `ed27ba16`。PHP 8.3.33 / 8.4.25 各 8 个普通文件观察：CSV 重复及 trim 后重复的表头保留最后一列，无名列和超出表头的值消失，短行凭空补为空正文；XLSX 同样覆盖重复列、丢弃无名及超出表头的数据。原始解析文件与 SHA-256、提交和树在 `/tmp/maccms-audit-20260910/import-followups/columns-source.json`，结果为 `columns-proof-{83,84}.log`。

两个解析器现在拒绝重复表头和没有任何有效表头的表格；非空值必须有对应列名。CSV 非空记录不得少于表头列数，清空最后字段必须保留明确的空单元格。空记录、全空的占位列和多余空列仍允许。XLSX 中省略的单元格具有正常工作表空白语义，继续按已命名列返回空值；稀疏列和稀疏行仍正常读取。

解析完成后，实际导入动作在任何行保存前核对整份表头与当前 writer 列信息。未知字段，包括写错大小写的 ID 表头，会使整份导入失败，避免过滤字段后意外变成新建。名称和分类表头必须存在。该规则对定制库的实际现有字段生效，不把安装时字段列表硬编码进控制器。

ImportColumnException 只携带整数源行和列，不包含原始数据、SQL 或文件路径。解析错误和字段表头错误统一返回 invalid_columns、row、column；九种语言提供修正提示。CSV 行号按逻辑记录计算，单元格中的换行不另计行；XLSX 使用工作表坐标。缺少必需表头时指向表头末尾后的待添加位置。保存前的整文件检查确保后面发现列结构错误时，前面有效行尚未保存。
