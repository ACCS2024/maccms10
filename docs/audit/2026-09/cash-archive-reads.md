# 提现归档查询

后台 `cash/index?archive=1` 沿用 `cash/index` 查看权限，展示原提现编号、账号、金额、积分、收款字段、原审核时间，以及归档结果、时间和操作者类别/编号。当前列表与归档列表提供互相切换的入口，归档页没有审核、删除、清空控件及金融写入脚本。操作者保留数字编号，不把当前账号名称冒充当时的身份；账号已删除仍能查看原记录。

后台分页统一要求正整数、每页最多 100 条、偏移最多 1,000,000；数组、布尔值、指数表示及越界值在查询前拒绝。筛选状态区分活动表的 0/1 与归档的 1/2，账号为合法正整数。关键词最多 200 字节、有效 UTF-8 且不含控制字符。查询不再次 URL 解码，不把 HTML 编码后的关键词送入数据库；HTML 输出显式转义，分页 URL 通过适用于脚本上下文的 JSON 编码生成。

归档关键词匹配保存的原始 JSON 片段，采用同一 JSON 编码及显式 LIKE 转义，因此引号、反斜线、百分号和下划线按字面查询。它是原始记录关键词搜索，包含字段名称和已存储的历史实体文本，不宣称是按解码后的收款账号专用搜索。后台活动表仍保留原账号 LIKE 搜索语义。

归档读取核对 SHA-256、原记录身份/状态，并验证显示所需金额、积分、时间、收款字段和操作者。归档表尚未迁移、内容损坏或查询失败时返回明确错误，不显示残缺的成功列表，不自动建表或改写异常记录。提现活动列表、详情、归档列表及关联用户名明确从主库读取，避免刚完成资金操作后从延迟副本看到旧状态；未宣称列表的多条 SELECT 构成同一时刻的快照。

验证使用真实后台构造、会话、权限刷新、路由、ORM 和实际模板，模板采用仓库的 `config/view.php`，避免测试继承模板包默认转义而与生产配置不符。覆盖 SQLite/MySQL、权限撤销、无登录、筛选边界、原字段关键词、无写操作、缺表、损坏快照，以及 PDO 层对所有相关 SELECT 的主库路由断言。主库断言检查实际连接调用，不等于生产主从拓扑演练。

会员与 API 的列表输入边界、旧收款字段编码及付款外部对账继续独立处理；生产迁移和发布未执行。
