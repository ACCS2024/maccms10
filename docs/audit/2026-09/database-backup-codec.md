# 数据库备份 A：分卷编解码与资源错误边界

范围仅为 `application/common/util/Database.php`。后台参数、目录、并发锁、失败文件清理与 CLI `DbBackup` 分别留待后续独立提交，不把本组当作完整备份系统验收。

## 已复现与修复

- PHP 8 在未打开文件的对象析构时执行 `fclose(null)` / `gzclose(null)` 抛出 `TypeError`；含 NULL 数据调用 `addslashes(null)` 在 E_ALL 下触发弃用错误。现在显式检查资源，关闭幂等，NULL 独立序列化。
- 原导出删除字符串中的 CR/LF，损坏多行正文。新格式使用十六进制值字面量，保留 NULL、空字符串、多行文本、引号、反斜杠、NUL 和二进制字节；文本显式使用 utf8mb4，二进制保持 binary。数值经 MySQL 转为字符串避免 PHP 浮点转换丢精度，BIT 使用无符号字面量，INSERT 排除生成列。
- 文件打开、短写、零字节写、分卷切换及关闭失败均检查返回值。新文件以排他创建方式写入、权限为 0600，同时间戳文件不会被追加或覆盖；公开 `close()` 和 `createdFiles()` 供后续调用方处理完成状态与失败清理。
- 原恢复只看行末分号，无法正确处理字符串中的分号、同行多语句或跨行字符串。现在流式识别引号、转义与注释，分批执行完整语句，未闭合 SQL 返回失败；每次调用关闭文件句柄。
- gzip 在执行首条 SQL 前检查压缩流完整性和 CRC，截断文件不能先执行 DROP 后才报错。输入须为配置目录内普通文件且不是符号链接。
- 导出临时规范连接字符集；恢复临时设置字符集、外键检查与 `NO_AUTO_VALUE_ON_ZERO`，在成功和执行失败后恢复原连接设置。连接本身丢失时，上层仍须捕获数据库异常。

## 真实验证

`python3 tests/run_database_audit.py` 使用新建 MySQL 8.0 容器、随机专用数据库和 Unix socket；数据库及 PHP 容器均关闭网络，不加载站点配置、不读取现有 SQL/备份、不访问业务数据库。

PHP 8.3.33 与 8.4.25 均在 E_ALL 下通过 **167 项检查**。覆盖普通与 gzip 真实导出/删除数据/恢复对比、1005 行分页、多个分卷、超过分卷阈值的单条记录、NULL/二进制/JSON/DECIMAL/BIT/DOUBLE/生成列、SQL mode 与字符集恢复、文件权限与名称冲突、无效参数、短写/零写、截断压缩文件及异常资源释放。

兼容性不是仅检查新格式自循环：另有固定手写旧格式 `.sql` 与 `.sql.gz`，实际执行 DROP/CREATE/传统带引号 INSERT，验证反斜杠转义、NULL、CR/LF、多行分号、注释及同行多语句的真实 MySQL 结果。该测试只执行仓库内作者确定的测试 SQL。

## 明确边界

- 导出每批最多读取 1000 行，单行与单条 INSERT 仍可很大；恢复完整缓冲一条 SQL。分卷阈值按未压缩字节计，单条语句可超过阈值。不是按字节严格限内存，也未实现跨表一致性快照。
- 本恢复器面向应用表备份与测试覆盖的旧格式，不宣称支持 mysql 客户端 `DELIMITER`、存储过程或任意第三方 SQL 脚本；SQL 恢复有 DDL 提交语义，失败不保证回滚已经执行的语句。
- gzip 校验接受单一完整压缩成员；拼接多个 gzip 成员或尾随额外数据会拒绝。旧正常一次生成的单成员备份经过验证；旧时间戳碰撞后追加产生的归档不被视为可靠备份。
- 本组不保证调用方创建失败时释放锁、清理半成品、校验缺失尾卷或阻止并发任务。后台控制器仍需后续独立修复后才能完整验收。
