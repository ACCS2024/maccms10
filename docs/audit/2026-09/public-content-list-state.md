# 公开媒体列表的发布与回收状态

本批只统一 Vod、Art、Manga 在公开 API 列表、详情元数据和关联目录中的发布/回收条件。保留父模块状态、资源权限、返回 DTO、原有关联顺序及分页接口。后台模型、受信任采集导出与全文资源授权没有被改为公共查询。

## 已复现的根因

使用当前安装 DDL、真实 ThinkPHP Request/控制器/ORM 和独立 MySQL。修复前控制器副本通过 Docker 单文件只读挂载运行，没有恢复或修改工作区文件。PHP 8.3.33、8.4.25 各确认 14 个触发：

| 入口 | 正常请求触发的问题 | 分类 |
| --- | --- | --- |
| `api/Art::get_list` | 不传 `status` 返回未发布文章；显式 `status=2` 可以选择未发布状态 | 公开读取边界 |
| `api/Vod::get_list`，`api/Art::get_hot`，`api/Manga::get_hot` | 直查绕过模型的 `mergeRecycleWhere()`，回收记录进入列表 | 公开读取边界 |
| `api/Vod::get_detail` | 仅按 ID 查找，未发布视频仍返回详情元数据 | 公开读取边界 |
| `api/Vod::get_year/get_class/get_area` | 只要求发布，没有排除回收来源 | 筛选元数据泄漏 |
| `api/Vod::get_latest_by_type` | 缓存整包命中后直接返回，视频下架后仍显示缓存标题 | 缓存边界 |
| `api/Topic::get_detail` 的两个关联列表 | 手工配置的文章/视频 ID 可带出隐藏媒体的标题、简介等 | 嵌套目录边界 |
| `api/Role::get_list/get_detail` 的视频关联 | 回填隐藏视频名称或详情元数据 | 嵌套目录边界 |

Art/Manga 的 `get_latest` 与各自 `get_hot` 共用同一缺失条件，回归同时覆盖。Ajax `data`、`guess_art`、`guess_manga`、`home_hot_tab` 和 Manga 普通列表已经经过模型回收过滤；本批验证这些实际路径，没有重复修改模型。

## 实现及兼容合同

- 新增 `application/common/util/PublicContentQuery.php`。只接受 `vod/art/manga`，固定 `*_status=1`；表存在回收字段时固定 `*_recycle_time=0`。使用数字条件元组，后续普通 `where` 条件不能覆盖它们。只读获取表结构，不执行迁移，不通过捕获任意 SQL 异常移除安全条件。
- `api/Vod.php` 的列表/详情/三个 facets，`api/Art.php` 的列表/hot/latest，`api/Manga.php` 的 hot/latest 接入该工具。文章列表显式请求非发布状态返回既有参数错误码 `1001`。
- Vod/Art 列表仍经过原验证与每页数量归一化，保留末尾主键倒序，避免相同时间或热度导致分页不稳定。列表在数据库查询处应用状态条件，然后进行原 DTO 加工。Meili 返回的 ID 集仍在最终 SQL 下接受这些条件。
- Vod/Art 总数继续由 `Base::getCountByCond` 使用原配置 `count_cache_sec`，强制发布/回收条件同时纳入计数 SQL 和缓存 key。旧的不含完整条件的计数缓存不会被复用。`total` 在既有 TTL 内可以短暂滞后；实际返回的 `rows` 仍现查并排除隐藏记录。没有对共享 Base 或后台查询增加默认过滤。
- Vod 最新列表保留原整包缓存，只在最多 60 个当前行 ID 全部仍发布且未回收时复用；存在隐藏、删除、重复、坏类型或超范围 ID 时重新计算。既有 `today_new_count` 等聚合值仍可能在缓存 TTL 内滞后，本批不声称强一致计数。
- 年份/分类/地区旧缓存仅含值，无法证明当前公开来源。本批使用实时 `DISTINCT` 查询，保留既有返回上限 **200 / 500 / 200**。移除这三个十分钟缓存会增加频繁筛选请求的数据库读取；`LIMIT` 只限制返回规模，不保证底层扫描行数。后续如优化，应保存可核验的来源 ID 或闭合发布/回收事件失效，不能恢复不可验证的旧缓存。
- `api/Topic.php` 仅两个子媒体查询、`api/Role.php` 仅两个子视频查询接工具。专题关联按原配置顺序跳过隐藏媒体；角色列表保留角色行，把不可见视频名称置为空串，角色详情保留 `vod_info=null`。父模块自身的状态/权限没有改变，Actor 未改。

## 验证

运行 `python3 tests/run_public_content_query_audit.py`：PHP 8.3.33、8.4.25 各 **265** 项真实 MySQL 检查。使用随机专用库、非 `mac_` 前缀、网络禁用、Unix socket；不读站点配置或站点数据。

覆盖默认发布状态、所有非公开组合、分页/空列表/父子分类、相同排序值的主键倒序、关联顺序、图片和链接 DTO、旧计数缓存哨兵、计数 TTL 保留、缓存行下架后重算、旧 facets 缓存哨兵、最后公开来源消失、510 个不同筛选值的实际 SQL/返回上限、旧表缺回收字段且无 DDL，以及后台显式查询未发布/回收记录仍可用。

Meilisearch 只替换外部 HTTP 传输：真实 Service、ListBridge、回表 ID 验证及最终 SQL 运行，输入包含已下架、回收、删除和正常 ID。正常分页及返回顺序保留；外部估算总数沿用原合同，可能滞后。没有发送外部请求。

兼容回归：双 PHP 各运行原 API 前缀/加工 **400** 项、A1 公开 DTO **600** 项及原生产 JS **13** 项、Vod 首页原查询 **156** 项。本文不把这些列表检查记作新的正文授权或购买事务验证。

## 留待独立批次

1. `ApiMeilisearchSuggest::orderedDbRowsByIds()` 的 `select()` 返回 TP8 Collection，但随后 `!is_array($rows)` 将正常结果丢弃；其异常兜底还会无差别移除 recycle 条件。该工具服务更多模块，另批处理并验证正常搜索回退。
2. Meili 桥对关键词条件的拆分、不同模块过滤条件支持和估算分页一致性需要独立兼容审计；本批不调整搜索语义。
3. 模板 `listCacheData`、整页历史缓存、静态文件、采集/导出具有不同生命周期或信任合同，不在本批五个 API 控制器的闭环声明内。历史 CDN/静态文件未被自动删除。
4. Vod 模型深分页先查 ID 后回表的两步间状态变化属于后续并发一致性检查；本批直接 API 列表为单次数据 SELECT，未修改共享模型的后台/导出行为。
5. Manga 完整章节/密码/阅读授权仍按资源链独立推进，不能用本批元数据状态统一代替资源权限验证。
